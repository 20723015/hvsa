# HVSA 设计与创新性独立审查（Luna）

审查日期：2026-10-11。审查范围仅为协议设计与创新性，不评价实验密度、论文表达、答辩表现、期刊会议门槛，也不把目录中的论文作为北交专硕毕业样本或同校毕业标准。材料包括目录 01–25 PDF、当前 HVSA 论文第 3/4 章、`CODEX.md`、`ASIG_VCM_REVIEW.md`、`VpdaUrvcm_LITERATURE.md`、中期答辩 v4 讲稿，以及参考文献 `016-2026-DVAFL.pdf`、`009-2026-MAFSA.pdf`。文中页码均指 PDF 文件页码（封面计第 1 页），而非论文印刷页码。

## 核心判断

**点一可以辩护为一项具体的分层协议设计贡献，但其新颖性落在角色与验证流程的重新分配，不在 PRG 掩码、线性同态哈希（LHH）、签名或一般的可验证安全聚合原语。** 01–25 中已出现 SHPRG+LHH 客户端验聚合结果、单 TA+LHH、可信辅助方掩码、签名/哈希验证和边缘层级聚合等分散先例。当前 HVSA 的可识别设计差异，是单 TA 持有用户种子并按实际在线用户集合计算一个全局解掩码量；边缘按组聚合并签发绑定组元数据的证据；云端只计算检查点/同步轮次的明文聚合和；边缘核对云端结果并本地重构共识模型。该责任划分与“每个用户直接验证云端模型”不同，也与“两服务端/辅助节点协作计算”不同，但必须在论文中正面比较这些先例，并把贡献限制在层级系统适配与协议闭环。

**点二当前的创新主张尚不能定稿。** 基础版本对齐在默认 `γa=1`、无陈旧衰减和归一权重时，代数上等价于把各旧版本模型的增量加到当前全局模型，即普通的增量聚合；不能单独称新补偿算法。DVAFL 已明确提出版本控制补偿（VCM），而 MAFSA 已明确提出边内同步、云间异步的层级组合和陈旧模型加权。点二剩余可辩护空间是：在 HVSA 的单 TA 掩码和 LHH 边缘核验约束下，把混合版本组包变成可选择、可解掩、可验证、可重放防护、可由边缘确定性重构的检查点事务。当前安全闭环中，DVAFL 矩校准的组级适配、矩统计认证和历史状态核验仍未完成；因此现阶段只能称“研究方向/待深化设计”，不能把这些验证机制作为已实现贡献。

在本次 25 篇硕士论文的文本中，**没有找到与 HVSA 完全相同的“云—边—端—单 TA、边缘验证、全局聚合掩码、边缘重构”组合**。这是有限语料内的结论，不等于全球首次或穷尽文献检索。按现有资料，点一作为专硕设计工作有合理成立空间；点二若把算法本体包装成新颖的 VCM，则依据不足。若要让点二单独成为扎实的协议贡献，必须把“组级异步为何需要检查点”“掩码释放如何绑定选中集合”“版本/策略/历史怎样由 ES 独立检查”“补偿是否改善并保持验证语义”闭合成一个方案。仅有一条半异步队列或公式重写，支撑力有限。

## 最近邻原文深读

### 1. #22《联邦学习隐私保护与安全聚合研究》（西南交通大学，2023）

- 摘要将第一项方案定位为跨筒仓联邦学习：SHPRG 生成掩码、多密钥 HE 保护随机种子、同态哈希验证聚合模型；并声称最多 N−2 合谋下的隐私性（PDF pp.4–5）。
- 协议用客户端持有的本地更新 (x_i)、SHPRG 种子和掩码上传 (y_i)，同时生成验证值 (h_i)，云端/聚合服务器聚合 (h_i)，客户端解密模型和掩码后检查聚合验证关系（PDF pp.29–33）。LHH 形式是 (h_i=\prod_j g_j^{x_i[c_j]})，线性组合可以聚合验证值（PDF p.22）。
- 与 HVSA 的实质交集：已存在“PRG 掩码保护本地向量 + LHH/同态哈希证明聚合和”的组合。故不能把“把 PRG 与 LHH 组合起来用于安全聚合”写成新贡献。
- 实质差异：#22 是 cross-silo、多密钥同态加密与参数服务器初始化；最终模型对聚合服务器不可见，合法客户端独立验模型。HVSA 是加性 PRG 掩码、TA 计算实际在线集合的全局解掩码，允许云端取得检查点聚合明文和，再由 ES 验证和重构；其主要新意须写在云—边—端职责拆分、组级证据和边缘检查位置上。两者保护目标与明文聚合信任边界并不相同。

### 2. #08《面向联邦学习的安全聚合方案研究》（长安大学，2024）

- 论文将系统定为 TA、Users、Cloud Server；TA 初始化系统并为用户生成/分发密钥，用户解密全局梯度并验证，云端聚合（PDF p.22）。
- 第四章扩展到多密钥动态可验证安全聚合，采用双陷门 HE、Shamir 掉线恢复与 LHH；用户由聚合梯度和验证值检查关系（PDF pp.44、51）。摘要明确称 LHH 提供聚合结果验证（PDF pp.3–4）。
- 与 HVSA 的实质交集：单 TA、LHH、在线集合/掉线容忍、可验证聚合都不是独立新颖点。HVSA 的差别是 TA 不给用户全局解密/验证钥匙，而依当前在线用户集合释放聚合掩码；边缘按组收集、签 metadata，并作为结果核验者，云端按系统定义获得聚合和。此差异合理，但应避免声称“首次单 TA+LHH”或“首次有掉线可验证聚合”。

### 3. #04《高效可验证的隐私保护联邦学习研究》（武汉理工大学，2023）

- 第一项方案基于 HE、Shamir、同态 PRG，支持掩码安全聚合、掉线和用户争议仲裁；第二项恶意服务器方案基于群组密钥协商和 HomMAC，客户端验证聚合梯度与标签（摘要，PDF p.3）。
- 其相关工作明确记录 Chen 等人的分层聚合：可信第三方在用户—聚合器、聚合器—服务器之间预分发掩码种子，随后聚合密文消掩码（PDF p.14）。这意味着“可信辅助方+层级掩码聚合”的大方向也有先例。
- 与 HVSA 的差异：该分层方案的描述是可信第三方预共享掩码、密文层级聚合并结合区块链；未见“ES 对 Cloud 解出的检查点明文和用 LHH 与 TA 全局掩码哈希作等式校验，然后 ES 重构共识模型”的同一流程。HVSA 要证明的是这组责任与信任边界组合的必要性和正确性，不是层级安全聚合概念本身。
- 此文另一个可验证方案的验证位置在客户端，按本地梯度标签和在线集合验证，摘要与实现参见 PDF pp.3、48–55。

### 4. #09《联邦学习下高效可验证安全聚合协议研究》（贵州大学，2025）

- 论文 RVFL 用聚合服务器、认证服务器、辅助节点群体和用户，用户用 PRG 种子掩码上传梯度及模型验证码；聚合服务器与认证服务器分别累计梯度/验证码，用户检查矩关系（PDF pp.23–28）。它进一步用博弈激励防止两个服务器稳定合谋（PDF pp.28–31）。
- 该方案实际有多个辅助节点、两个服务器，安全论证依赖服务器/节点合谋边界；验证值是随机矩阵与单位向量构造的模型验证码，不是 HVSA 的 LHH。其协议以同步运行、用户验证为核心（PDF p.32）。
- 与 HVSA 的交集是 PRG 掩码、服务器端辅助角色、独立聚合正确性检查。区别是掩码与模型验证码构造、实体数和信任模型不同；它也提醒 HVSA 的“轻量验证”不能仅凭定长 hash 主张在所有方向优于已有协议。

### 5. #23《基于联邦学习的安全可验证及拜占庭鲁棒隐私保护方案研究》（兰州理工大学，2025）

- SVFL 的三个角色为用户、聚合服务器 AS、辅助服务器 HS；每位用户用自己的密钥加密更新、对更新哈希签 BLS 签名，AS 通过重加密聚合，HS 协助安全密文转换；用户用 Hadamard 积标签验证聚合结果（摘要与系统模型，PDF pp.3–4、30–33）。后续另有双 AS/HS 的拜占庭鲁棒方案（PDF pp.36–37）。
- 交集是辅助方、签名、用户对聚合正确性的验证与动态掉线。差异是多密钥 HE/PRE、BLS、密文转换和 Hadamard 校验；非单 TA、非边缘组级 LHH 等式。因它已经组合了“签名+可信/半可信辅助方+可验证聚合”，HVSA 需清楚指出验证输入、生成者、最终接受模型的实体以及安全假设的差别。

### 6. #19《Malicious-Resistant Non-Interactive Verifiable Aggregation for Federated Learning》（华东师范大学，2024）

- 封面明示这是 2024 年电子信息专业硕士论文（PDF p.2）。摘要提出 lwMVC/MRNIVA，为跨设备 FL 提供非交互、抗恶意服务器的可验证聚合，核心使用轻量级多方可验证计算、半门协议和优化 POT（PDF pp.6–7）。正文涉及 garbled circuit/MVC/POT，而不是 LHH 与 PRG 掩码（PDF pp.22–33）。
- 与 HVSA 的交集是对恶意聚合端的正确性验证及资源受限考量；机制层面差异较大。它是验证领域的功能性近邻，但不构成 HVSA 层级角色流程的直接复刻。

### 7. #25《面向设备异构性的异步联邦学习算法研究》（西电，2025）

- PP-QuicklyFL 将成对掩码协议嵌入异步缓冲队列，并以哈希链绑定上传顺序、防重排/重放；客户端异步生成、服务器协调种子并聚合（摘要 PDF p.4、方案 PDF pp.53、58）。它保护异步更新隐私与时序完整性，不是对不可信云返回的解掩码聚合和进行 LHH 验证。

## 点一：当前设计与可辩护的创新边界

### 当前闭环

按 `chapter03.tex` 和 `CODEX.md`，当前点一是：用户与 TA 通过密钥协商建立种子，逐轮 PRG 得到加性掩码；用户只上传一份掩码向量；ES 形成组掩码和并计算 LHH，签名绑定轮次、基模型摘要、在线用户集摘要、组样本量与组哈希；TA 根据各 ES 的实际在线用户集计算全局掩码和及掩码哈希；Cloud 求出全局明文和；ES 核验 `H(W_sum_raw)·H(M_global)=∏H_k`（按协议的群/标量记法），成功后本地计算共识模型。用户端没有逐维验证密码学开销，验证通信为定长，LHH 计算本身仍为 (O(d))。设计明确假设 TA 全信任且不合谋、消息走理想安全信道；隐私目标保护单客户端而允许组/全局聚合公开，完整性需要诚实 ES。不得把“ES 可能恶意时仍保证 Cloud 完整性”当作当前安全结论。

### 创新结论

1. **已知原语不能占创新中心。** #22 先例已是 SHPRG+LHH，#08 是单 TA+LHH+掉线和用户验证，#04/#14/#23 又分别覆盖 HPRG/HE/HomMAC、轻量验证与辅助服务器签名。因此“掩码+同态哈希可验证聚合”是已有设计空间。
2. **当前最可辩护的是协议编排与部署层级。** HVSA 把解掩码凭据从可逐用户解密/验证端转成 TA 对真实在线集合的一个聚合掩码；将 LHH 检查从用户端/验证辅助服务器移至掌握组状态的 ES；让 Cloud 做跨组解掩码和，ES 决定共识模型。它要解决的是客户端不参与额外交互、按组聚合、掉线、云端结果核验与低维验证通信之间的工程/协议矛盾。
3. **是否达到“实质设计贡献”，而非简单改名组合，取决于三件事。** (a) 形式化证明在线名单、组摘要、mask hash、LHH 聚合等式共同覆盖丢组/篡改/重放时的检测语义；(b) 证明在公开聚合和与 N−2 客户端合谋前提下剩余两个诚实客户端保护目标成立，区分同一检查点的组数和客户端数；(c) 用逐项功能表比较 #08、#22、#04、#09 和 #23，解释为何“单 TA 聚合掩码+ES 验证+ES 重构”更适合云边端 HFL，而不是仅列组件。
4. **边界应写清楚。** LHH 等式证明的是群中线性聚合关系；签名证明元数据来源/绑定；两者不自动证明 TA 的状态、客户端训练正确性、统计非线性函数、恶意 ES 行为或恶意用户更新质量。当前威胁模型也不覆盖所有边缘节点恶意。

判定：**点一可以作为硕士专业学位论文的一项协议/系统设计贡献，且已有 BlockSys 录用作为研究成果证据；但只能作“在既定信任前提下，将已有掩码与线性验证机制适配到层级联邦聚合，并形成单 TA—ES—Cloud 的验证和重构流程”的受限主张。不能写成首次 PRG+LHH、首次安全可验证聚合、首次单 TA 掉线安全聚合。**

## 点二：当前基础版、计划版与最近工作

### 已实现基础版的代数判断

`chapter04.tex` 将旧基版本组包对齐写为对组模型补偿 (C_k=S_k(t_k)\gamma_{vcm}(W(t)-W(t_k)))，在组级汇总并除以检查点参与样本量。令组上传模型为 (U_k=W(t_k)+\Delta_k)。当 γ=1、无额外陈旧衰减、采用归一化样本权重时，

\[
\frac{\sum_k S_k[U_k+(W(t)-W(t_k))]}{\sum_k S_k}
= W(t)+\sum_k\frac{S_k}{S_Q}\Delta_k.
\]

因此，这个默认版本就是把 stale group model 的增量 Δk 加到最新共识模型上。它解决了版本基点不一致的实现问题，可作为系统正确性/对齐步骤；**它不构成新的补偿公式**。该恒等式的前提是每个组的更新相对于该组已知的基版本定义、采用归一化样本权重且 γ=1；不同组可以来自不同基版本，组内汇总时需有一致基点。在此前提下，它不依赖本地 SGD 步数。若把“版本差补偿”进一步解释为恢复陈旧梯度在当前模型上的即时梯度，则多步本地训练会影响该解释，但不改变上述模型增量代数恒等式。

### 文献对照

- DVAFL（Chuyi Chen 等，《Toward Efficient and Scalable Asynchronous Federated Learning via Stragglers Version Control》，IEEE TMC 2026，PDF pp.1–2）：提出动态窗口 DWP 和 VCM；VCM 收集版本历史，将 straggler 更新对齐到当前模型，补偿量为版本差，并提供简单直接版本和矩校准版本（PDF pp.6–8）。这已经覆盖“版本差补偿”本身，HVSA 不能把直接 VCM 当原创机制。
- DVAFL 矩校准形式依赖客户端参与次数校正的一阶/二阶动量或矩值比例（公式 13 起，PDF pp.7–8）；讲稿拟把这些标量统计汇总到组，组系数约为 (B_k/G_t)。这是从客户端到组包的适配候选，不是已完成协议。由于 (B_k,G_t) 依赖非线性统计，LHH 对向量和的线性同态性不会自动认证该系数确实由对应隐藏更新按规定计算。
- MAFSA（S. Zhang 等，Engineering Applications of Artificial Intelligence 172 (2026) 114369，PDF pp.2、5–7）：有 Cloud/Edge/Client 三层，边缘内同步、Cloud 收到任何边缘更新即异步全局聚合；对陈旧模型用 (\alpha w_{current}+(1-\alpha)w_{stale})，且 (\alpha=e^{-\beta E})（PDF pp.5–7）。所以“分层+跨边异步+陈旧处理”也已有先例；其公式是新旧模型权重混合，不等同于 DVAFL 的版本差补偿或 HVSA 的经验证组包后置补偿。
- #25 的 PP-QuicklyFL 是客户端异步缓冲和 hash-chain 有序成对掩码，侧重隐私与顺序完整性；不是针对云端全局聚合值的 LHH 正确性核验。

### 计划版要成为可辩护贡献的必要闭环

点二可强调的不是新的“陈旧更新数学公式”，而是**版本补偿如何在已验证安全聚合协议中执行**。最低需要完成：

1. 组包必须绑定唯一基版本、参与者/样本量、掩码承诺、包令牌及策略配置；检查点明确选中集合之后 TA 才释放选中组的掩码和，避免未选包获得解掩码材料。安全主张限于冻结的选中集合 Q 上的结果与策略；Cloud 对候选全集的遗漏/审查不在当前目标内，不能把抗审查当作已具备性质。
2. ES 对每组声明的旧/新版本、参与计数、权重来源和补偿参数独立复算；失败时 fail-closed，不更新模型。TA 权威账本/检查点回执需防止 Cloud 改写版本或重复消费组包。
3. 对 VCM 矩校准，明确所用矩的定义、客户端到组的加权规则、偏差校正和初始化；说明统计值能否从 ES 已见消息确定性重算。若 ES 无法看到可复算的统计输入，则应说明认证对象是客户端/组提供的声明值，还是由历史状态递推得到的值；把这些值绑定到 package/token 和检查点版本，并由 ES 按公开规则独立复算。LHH 仅证明线性和关系，不证明矩范数、比值、阈值分支等非线性计算与隐藏更新数学一致。按现有半诚实客户端前提，后者不是必须达到的安全目标；只有声称抵抗恶意客户端伪造统计时才需要额外证明机制。
4. 分开报告协议新意和优化效果。DVAFL/MAFSA 的完整系统若没在同一框架忠实实现，就不要做优劣或性能超越断言；可以用直接公式对照、相同异步轨迹消融及安全性反例说明当前层级约束改变了哪些适用条件。

判定：当前“组级半异步 + 默认增量对齐”**是合理扩展，但不是足够独立的新算法贡献**。计划中的“DVAFL 矩校准的组级适配+策略/统计可验证+检查点授权与历史状态保护”在概念上可能形成第二项协议设计贡献，判断依据是它与现有方法的实质差异及其定义、推导和核验关系是否闭合；实现进度是成熟度问题，不单独决定设计是否新颖。按目前材料，策略变量、组级统计口径及 ES 核验对象仍有未闭合处，故尚不足以作肯定结论。讲稿 P7–P9 的阶段口径是正确的，应继续维持。

## 对专硕论文设计贡献的综合结论

- **点一：成立空间较大，但应主张为系统与协议贡献。** 现有协议原语和验证思路已分别存在；HVSA 的贡献是面向 cloud-edge-end 层级联邦学习，将单 TA 掩码恢复、分组证据、云端解掩码、边缘 LHH 核验和边缘模型重构统一成可运行安全边界。其合理场景是弱终端少交互、边缘按组汇总、Cloud 不可信而 TA/ES 的信任角色明确的场景。若只把已有组件拼接起来、没有阐明角色放置为何必要或没有协议证明，则会显得是组合/工程集成；当前论文有具体公式、状态流与威胁模型，具备进一步论证为设计贡献的条件。
- **点二：当前版本不宜独立声称创新充分。** MAFSA 已有层级异步组合，DVAFL 已有版本差补偿及矩校准，默认 `γ=1` 的基础版本对齐退化为常规增量聚合。点二需要靠验证约束下的新状态转换闭环体现设计创新性，而非用新命名；尚待实现不等于设计没有创新，当前关键是把方案定义和核验关系论证闭合。
- **毕业充分性：仅从设计新颖性角度，点一+一个完成闭环的点二可形成专硕论文的两个有递进关系的设计贡献；按当前材料，点一足以构成一个可辩护贡献，点二仍是未闭合的设计/验证计划。** 是否满足具体学院的毕业审核或授位要求不能从这 25 篇异校论文推断，须依北交学院正式标准、导师/评审要求和已确认成果审核。这里不对实验密度和写作质量作结论。
