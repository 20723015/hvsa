## 1. 验证器修复

补查协调修改时发现：旧 `EdgeServer.verify_global_result` 验证每条证据的签名和同态等式，但没有检查组证据是否覆盖同步轮的全部边缘且每组恰好出现一次。

设云已经收到某组掩码聚合 `S_k` 和合法证据 `H_k`：

- 云删去该组证据，同时提交 `X'=X-S_k`，旧验证入口接受。
- 云重复该组证据，同时提交 `X'=X+S_k`，旧验证入口也接受。

构造只使用云本来收到的掩码组和与签名证据，不需要 TA 种子、客户端明文或边缘签名私钥。原来“仅删证据、结果不变”的测试没有覆盖这项能力。

修复在验签前要求证据中的边缘集合与 TA 提供的同步轮注册边缘名单完全一致，且条目数相等；缺组、重复组、未知组和无法取得验证名单均拒绝。合法证据改变排列顺序仍接受。它保留研究点一原有的全组同步屏障，没有把空组或异步 checkpoint 纳入本次协议。

修复前复现记录及对应源码：

- `results/point1_compare/review_20261018/hvsa_pre_fix_evidence_set_probe.json`
- `results/point1_compare/review_20261018/hvsa_pre_fix_edge.py`，与复现时记录的 SHA-256 一致。

这属于实现漏检修复，不作为新增密码学创新。未修改已经提交的论文或答辩 PPT。

回归验证：`tests/test_point1_compare.py`、`test_point1_measurement.py`、`test_point1_artifacts.py`、`test_point1_performance.py`及既有`test_crypto_primitives.py`共33项通过，覆盖真实完整链路、协调漏组/重复组、合法证据换序、输出域、关闭验证语义、上传前/后掉线、输入摘要、记录缺失和归档损坏等检查。

随后复查输入域发现：旧入口会接受object大整数加曲线阶、带小数浮点返回值及错误二维形状；哈希原语的取整/展平/模阶语义不能代替协议输出格式检查。修复前真实反例及原源码已保存于 `results/point1_compare/review_20261018/domain_pre_fix/`。同步验证入口现要求长度等于公开维度的一维有符号64位整数数组，拒绝越域和错误形状；合法大端int64仍接受，哈希原语不改。这同样属于实现修复。
