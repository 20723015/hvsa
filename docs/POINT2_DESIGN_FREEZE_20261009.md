# 研究点二首版设计：份额驱动的可验证组级半异步安全聚合

版本：point2-pacing-v0，2026-10-09。

状态：设计规约已具体化，供最小原型实施；候选调度器、认证快照与联合份额提交均尚未实现或完成效果验证。本文取代 2026-10-08 研发路线中未冻结的容量、触发和选集描述。

## 1. 研究问题与主线

固定组级异构速度时，快组可能被反复采纳。即使每次按实际样本数聚合，跨检查点累计的聚合系数仍可能偏离注册数据份额。原轨迹 CIFAR10 Non-IID seed 42 的快组数据份额为 20.38%，平均聚合系数为 35.30%；这证明有采纳份额偏移，尚未证明它造成精度下降。

点二研究目标：**在客户端更新不可逐个公开、云端不可信的条件下，用有限等待和确定性选集干预组包采纳节奏，并核验规定截止点前的候选集合、触发决策及模型与份额状态的提交。**

整体流程：客户端一次掩码向量上传，边缘组内封包并直接登记；云端缓冲；依据累计份额决定等待与选集；独立核验规定时点的认证候选全集及调度；恢复选中聚合和并进行基版本对齐；TA 确认后联合推进模型、份额和 token 消费状态。

研究机制是“调度及其可验证执行”这一组合。组包、安全聚合、LHH 与 VCM 是承载该机制的基础，不拆分包装成多个新增算法创新。

## 3. 聚合公式与份额状态

注册样本量固定，组 g 的目标份额为 π_g=N_g/N_all。实际组包样本量 S_k 由成功上传的用户及其已认证样本数求和，不把掉线用户计算在包内。

组包本地增量为 Δ_k=w̄_k−W(r_k)。选中集 Q 的实际样本量为 S(Q)=Σ_{k∈Q}S_k，权重 p_k=S_k/S(Q)。模型转移为

\[
W_{v+1}=W_v+\sum_{k\in Q}p_k\Delta_k.
\]

在 γ=1、无衰减时，VCM 的 Σp_k[w̄_k+W_v−W(r_k)] 与上式代数等价。新模块干预 Q 和提交时刻，不修改 Δ_k 或 p_k。

定义 a_g(Q) 为该组在 Q 中的样本权重，未入选时为零。维护

\[
C_g(0)=0,\qquad C_g(v+1)=C_g(v)+a_g(Q),\qquad \sum_g C_g(v)=v.
\]

选集评分使用原候选的累计平均系数偏移：

\[
J_v(Q)=\max_g\left|\frac{C_g(v)+a_g(Q)}{v+1}-\pi_g\right|.
\]

这是调度代理指标。它不等于梯度贡献、训练损失或全局更新偏差，也未证明降低 J 必然提高准确率。首版 C、π、J 采用整数分子/正分母的规范有理数；实现需记录序列化与计算成本，不能视为零开销。

## 4. 三臂确定性决策规则

对当前未提交版本 v，由权威登记日志构造每个已关闭 slot h 的完整合法就绪集合 E_v(h)。每个组至多出现一次。FIFO 依据 TA 登记序号排序，以 token 作最终并列裁决。

上次提交后的权威待决候选状态是初值，随后应用连续登记与过期增量；不能只计入本版本新登记包而遗漏此前保留的慢组包。

**窗口开启 h₀：**上一次提交后，首次 |E_v(h)|≥3 的已关闭 slot。它由日志确定，云端不能自由延后开启或重置计时。冻结截止 h_d=h₀+B。

**打开时的参照：**Q₀=FIFO₃(E_v(h₀))，J₀=J_v(Q₀)。整个窗口内 W_v、C(v)、π、配置及这个参照保持不变。

**份额最优选集：**枚举 E_v(h) 中全部三包子集，按下列键从小到大选择唯一 Q*(h)：

1. J_v(Q)；
2. 最大组包陈旧度 max(v−r_k)；
3. 陈旧度总和 Σ(v−r_k)；
4. 按 TA 登记序号排序的三元组；
5. 规范排序的 token 元组。

五组时至多有 C(5,3)=10 个子集；这只是首版规模，不代表大规模成本已解决。

| 臂 | 触发与选集 |
| --- | --- |
| A：立即 FIFO | h*=h₀，选 Q₀ |
| B：固定窗口 FIFO | **始终等到 h_d**，从 E_v(h_d) 取 FIFO 最早三个；不使用份额评分，不提前结束 |
| C：份额驱动窗口 | 若 h₀≤h<h_d 且 J_v(Q*(h))<J₀，在**首次**满足条件的 slot 提交 Q*(h)；若此前都不满足，在 h_d 提交 Q*(h_d) |

因此，份额目标没有达到不是放弃理由。**C 臂窗口到期仍提交评分最优的三个合法包，B 臂提交 FIFO 三包。**所有正常提交的包数都为三。

若 h₀ 时已有四或五个合法包，C 臂可在 h₀ 立即选出优于 FIFO 的集合。若只有三个包，且没有新增可改善候选，C 臂会等满 B。三臂最大等待一致不表示实际等待一致；C−B 首先检验整个份额驱动触发与选择机制，尚不能拆分提前触发和选集各自的贡献。

首版窗口内固定版本、禁止主动撤销合法就绪包，故一旦开窗，到期仍至少有三个合法候选。异常的撤销、数据不可取或人数不足不得悄悄改成两包聚合：记录异常/失败，暂停该决策并恢复或停止，不作份额提交。正常实验不混入这种故障语义。

## 5. 任务与组包生命周期

每个组状态为 IDLE、TRAINING 或 PENDING。被暂缓的组保持 PENDING；首版没有额外的客户端本地训练量调整或单独冷却算法。

1. 空闲组在下一 slot 启动一个新任务，读取此时最近已提交的模型及基版本，固定任务序号 j。
2. 任务耗时 d_g、用户掉线、上传丢失和 minibatch 随机性由外生配置及 (seed, namespace, group/user, j) 确定。不同臂使用相同索引规则，禁止按事件遍历顺序消耗一个共享随机流。
3. 完成任务后，足够用户上传则封包并登记。未封包任务终止，次 slot 可启动下一任务。超出陈旧上限的完成结果作显式过期处理，不登记为合法候选。
4. 未消费的合法包保持待决，不启动该组下一任务。成功采纳才释放它；基版本过期也通过权威 EXPIRE 记录释放。
5. 成功提交 v→v+1 后，检查剩余 PENDING 包：只有 v+1−r_k>3 才因版本过期；**等待窗口到期、份额超额或落选本身不构成过期**。过期不增加 C，不作为已采纳贡献。
6. 已在训的其他组继续完成原任务，保持原基版本，不因别人提交而凭空更换训练起点或完成时刻。

每个 slot 的仿真顺序冻结为：空闲组启动任务；处理该 slot 所有任务完成与封包登记；统一关闭该 slot、确定其日志截止序号；作一次调度决策并模拟提交；执行提交后的过期释放。释放组的下一任务只能在次 slot 启动。每 slot 至多提交一次。

**离散事件仿真必须按各臂自己的状态重新生成事件。**固定的是外生任务耗时和随机输入，提交、释放、后续启动、完成、基版本与选集都可不同。旧 event_trace.json 只能用作诊断和原基线核对，不能作为新策略的固定到达输入。

## 6. 规定时点的认证快照

原 TA 注册仅有 token、组和基版本，不能直接作为完整合法候选快照。拟新增由边缘直接提交的认证描述：token、任务序号、edge_id、基版本/模型摘要、实际用户集合、样本量、人数、掩码包/证据摘要及数据可用性承诺。TA 依据固定注册样本数复算 S_k，分配不可回退的登记序号。

TA 在受信逻辑 slot 关闭后，认证**该 slot 的完整日志前缀截止 q(h)**。原型使用逻辑 tick；将来真实部署需要 TA 单调计时及明确 slot 长度。云端的 created_tick 或自报时钟不能充当超时依据。认证 slot 不要求所有客户端响应；截止后登记的包归下一 slot。

快照/证书至少绑定：epoch/session、checkpoint v、配置摘要、前一提交回执摘要、C(v) 摘要、slot h、权威截止序号 q(h)、日志前缀根、完整合法候选清单摘要及前一证书摘要。

边缘必须能从 TA 独立取得规定前缀的完整候选清单或完整性证明。只有根或每包成员证明，只能证明“这些包在日志内”，不足以证明“没有遗漏别的包”。首版采用完整清单和日志增量复算，不预先引入 ZK 或复杂认证数据结构。

**截止点由规则决定，不由云端选择：**

- A 必须用 h₀ 的 q(h₀)。
- B 必须用 h_d 的 q(h_d)。
- C 必须用首次严格改善的 h*；不存在提前改善时用 h_d；绑定 q(h*)。

验证器需要核对从上次提交至 h₀ 的连续日志/证书，确认没有更早开窗；再核对 h₀ 至 h* 的完整前缀，确认没有跳过更早满足提前条件的 slot。不能只验证“当前这份快照签名有效”。TA 在授权决策时同样核对 v、前态、上述唯一 h* 和截止点，并对该版本的决策签发唯一冻结凭证。

规定截止点之后正常到达的包不改变本次冻结集合，属于后续决策；验证器也不应要求将它们加入已冻结的本次集合。

## 7. 冻结、解掩码与联合提交

冻结凭证绑定 decision_id、v、配置、h₀/h*/h_d、q(h*)、快照摘要、C_before、π 摘要、J₀、触发理由、唯一 Q、实际样本量与原模型摘要。

先验证调度并冻结唯一 Q，再为该决策请求对应聚合掩码。TA 不为同一冻结决策释放另一选集的掩码；重试复用同一决策及 Q。窗口关闭后的新增候选不能成为云端改选理由。

原 LHH、组签名、基版本与权重检查继续负责选中聚合和及重构。边缘复算 W_next 和 C_next。提交回执共同绑定冻结凭证、聚合结果摘要、W_before/W_next、C_before/C_next 与选中 token。

**TA finalize 是逻辑生效点**：在同一权威事务中落地版本、token 消费、模型摘要、份额前后摘要及完整 C_next。阶段性冻结和 prepare 可以写日志，但不能推进 C 或消费 token。云端随后幂等 publish，边缘与客户端延迟通知后查询已提交结果再继续相应任务；无需等待所有客户端收到通知才推进全局。

重复 finalize、publish 或通知不能重复增加 C。同一版本仅一条成功提交。认证或聚合验证拒绝不推进 W、C 和 token 消费；允许无关准入日志继续追加，不把它误判为拒绝后“所有日志均不变化”。

冻结后的瞬时数据不可取先重传/恢复，不能自行换成另一选集。TA 判定终止时记录显式终止；若已释放聚合掩码，首版不允许把这些向量移植到其他选集继续查询。网络故障恢复、持久化与多轮泄露需要在安全阶段另做完整验证。

## 8. 安全目标、假设与必要性实验

目标准确表述为：**对规定截止点前已由 TA 登记、满足冻结合法性条件的组包，验证云端是否按规定执行触发、选集及联合提交。**

假设沿用可信且不合谋 TA、诚实客户端训练与真实登记权重、诚实边缘核验；强隐私仍依赖声明的非合谋人数及密码学条件。签名不证明正确训练、真实数据量或云端已收到完整向量。数据可用性依赖边缘保留和重传，费用需要测量。

不保证未登记包可见，不阻止云端拒绝服务，不保证离线组一定被采纳，不直接宣称无偏或无饥饿。有限窗口限定算法的决策等待，不保证密码学验证、网络与恢复在同样时间内完成。

| 攻击 | 新验证需要检查的内容 |
| --- | --- |
| 聚合和正确，但隐藏截止前合法慢组 | 规定 q(h*) 对应完整候选清单及确定性重选结果 |
| 使用一份有效但更旧的快照 | h₀/h* 与 q(h*) 必须由连续日志及唯一决策规则推出 |
| 跳过较早满足提前条件的 slot | 连续前缀中的首次触发性 |
| 伪造超时或重开等待窗口 | TA slot 关闭证书、首次 h₀ 与 h_d=h₀+B |
| 替换 C、π 或组包样本量 | 前一提交状态、固定注册权重、配置摘要与状态复算 |
| 漏推进或重复推进 C | finalize 原子性、回执绑定与幂等恢复 |

选择违规攻击只在确有另一不符合冻结规则的三包集合时计入 applicable；若恰好只有三包，不能随意漏掉一个并声称攻击仍满足 K。对“只核验选中集”的削弱版本与完整验证版本作接受/拒绝对照。

应先验证的性质是 C 的归纳不变量、单次消费、规定截止点的决定性与拒绝/恢复语义。份额误差界须另加可用性条件；任何训练收敛结论都需独立分析，不能继承 FedNova 或其他调度方法的定理。

## 9. 三臂实验与晋级

阶段一：不执行模型训练的离散事件仿真。三臂各自生成到达/提交事件，输出任务序号、启动/完成、基版本、登记序号、合法队列、窗口证据、Q、C 和预计训练工作量。检查任务不能提前完成，份额状态只随提交推进，所有提交恰为三包，同 tick 顺序和恢复不产生重复采纳。

共同时间预算先固定 T=200 ticks，不按每臂达到 20 checkpoints 就分别停止。20-checkpoint 结果仅作与旧设置对照的次要观察。开发种子 42–44 不作为留出验证。

阶段二：复用同一事件引擎作三臂配对训练，固定划分、初始化和按 (客户端、任务序号) 索引的 minibatch 随机性。数据和初始模型摘要、外生过程、代码与配置均保存。任务启动时即可计算并缓存本地增量，逻辑完成时才允许登记；记录真实已执行 SGD 步和样本访问量，包含等待、过期、未封包、上传丢失与截止点仍在途任务的已执行成本。

报告共同时间上的最新已发布模型精度，并报告共同实际训练工作量网格上的精度。网格取各臂已执行训练量的共同覆盖范围，每个点使用不超预算的最后一次发布模型；在途训练已经执行也计入。较晚提交的未发布新模型不能拿来填更早预算的结果。

主要比较 C−B，次要比较 C−A 和 B−A；同时看最差种子、尾段趋势、累计份额偏移、最长组缺席跨度、实际等待、陈旧度、发布次数及未采纳训练成本。三臂只有同一最大窗口，触发时点本身也是机制的一部分；有趋势后增加相同触发时点的选集消融，再拆分等待控制与份额选集的贡献。

算法晋级起点：原 Non-IID 两任务中，C 相对 B 的共同时间终点配对均值至少 +0.5pp 且至少 2/3 开发种子为正；尾段或最差种子出现明显倒退时不直接晋级。满足起点也不代表稳定效果，须冻结配置并用未参与筛选的 seeds 52–56 及更长视界确认。若只改善 J 或只胜 A 而未胜 B，不作份额模块有效结论。

时间到精度、IID、速度与标签相关及更大异构程度属于后续扩展；目标阈值和参数选择须使用事先规则或独立验证集。不得从测试结果选择种子、B 或最佳训练截点。

阶段三：只有机制差异与效果值得继续时，接入完整安全实现。对拍浮点明文、相同编码的量化明文与安全实现；量化明文和安全实现按同一整数语义比较，浮点差异单独报告。测量训练、上传、TA 快照与掩码、边缘核验、提交及恢复的关键路径、字节和存储。模拟 ticks 不能直接代表完整协议端到端加速。

## 10. 新颖性与当前可主张范围

已有归一化、到达节奏调度、代表性缓冲和可验证选集的先例。FedCompass 调整本地训练任务量；首版固定训练量并控制采纳及后续任务启动。AdRo-FL 已有组内人数/隐私选择约束；本候选维护跨检查点累计聚合系数，并核验规定截止点的触发。上述差异支持继续研究，尚不足以证明独立创新。

需继续核对原先研发路线列出的 FedCompass、AdRo-FL、CrowdFedAsync、Buffalo 等近邻；本次规约冻结不新增“首次”等主张，也未完成全文比较。

当前可说：已发现可复核的参与份额偏斜，形成固定 K 的调度及认证设计；已完成的原点二原型提供安全聚合与提交基础，新模块待最小仿真与配对训练验证。缓存校准暂缓，默认 VCM 保留为基版本对齐组件。

进入研发的验收顺序：先验证事件生成和状态规约，再判断 C 是否比只等待更有效，最后判断认证调度的必要性及完整成本。任何一项不足，都不能用改名或新的签名字段补足结论。
