## 2. 诊断过程 (假设 → 排除)

| # | 假设 | 方法 | 结果 |
|---|------|------|------|
| 1 | 代码 bug (版本错位) | 检查 `p2_global_model_history` 赋值 | 无 off-by-one, 排除 |

| 3 | 补偿幅度过大 (限幅可救) | 新增 vcm-mode: `span`(除版本跨度)/`clip`(截断 raw_sum 10%) | 与 full 逐值相同: 选中组包跨度恒=1, clip 限幅未触发; 且方向性错误, 排除 |

## 3. 根因 (机制级)

### 3.1 机制的数学形态

**Stale reuse 混合** (user.py `p2_train_mix_mask_and_upload`, Ours 规则):

```
ρ_i = ρ_max · exp(−β_c · E_i),  E_i = global_version − stale_version
w̄_i = (1 − ρ_i) · w_new + ρ_i · w_stale     (上传的明文模型)
```
其中 `w_stale` 是用户**上一次本地训练后的模型** (上传失败时缓存), 非全局模型。

**Direct-VCM 补偿** (cloud.py `p2_apply_vcm_and_average`):

```
C_k = S_k · γ · (W(v) − W(r_k))    加到组包 raw sum 上
```

### 3.2 失效链条

1. **VCM 前提**：组包贡献 ≈ "在 r_k 上训练的纯增量" (w_new − r_k)。
2. **reuse 破坏前提**：混合后上传值含 `w_stale`——Non-IID 下这是带**本地类别强偏置**的历史模型，
   组包贡献 = (1−ρ)(w_new−r_k) + ρ(w_stale−r_k) + r_k，不再对齐单一基线。
3. **补偿方向错位**：`W(v) − W(r_k)` 反映最近全局更新方向；Non-IID 下每个 checkpoint 只覆盖少数类别，
   该方向与组包真实偏差方向不相关 → 补偿从"修正"变成"系统性错误强加"。
4. **幅度放大**：Non-IID 下 `|W(v)−W(r_k)|` 跨类别漂移幅度大，comp 每轮数百 (s44: 580~752)，
   与组包真实贡献同量级 → 强改模型、震荡不收敛。
5. **rho 调轻只减一半**：ρ 0.5→0.1 只压缩 stale 偏置注入，补偿错位本身不变，故只能修复到 85.5 而非 87.3。

### 3.3 各场景自洽性

| 场景 | 为什么 OK / 为什么崩 |
|------|---------------------|
| IID G5 (+1.5pp) | stale 偏置≈0 (本地与全局同向); `W(v)−W(r_k)` 幅度小 → 补偿温和且方向正确 |
| Non-IID G3+VCM (+0.6pp) | 无 reuse, 组包=纯增量, VCM 假设成立 → 修正正确 |
| Non-IID G5 (−6.3pp) | reuse 注入类别偏置 + 补偿错位叠加 → 系统性错误 |
| Non-IID G4 (−0.1pp) | reuse 单独: 模拟中上传失败不省训练成本, 无正收益, 只剩偏置成本 |

### 3.4 辅助证据

- **崩溃 seed comp 高、正常 seed 低**: s44 comp 每轮 580~752 vs s12 后期 85~300 → 补偿强度与性能负相关。
- **γ 敏感性失效**: 调 γ 减半不加不减 — 幅度不是主因, 方向才是。
- **span/clip 逐值相同**: 选中组包 `v−r_k` 恒=1 (K=3 高频 checkpoint), span 归一无效; clip 限幅 (10%) 从未触发。

---

## 4. 结论

> Non-IID 下完整方案掉点的根因 = **stale reuse 把用户历史模型偏置注入组包，
> 使 Direct-VCM 补偿的前提 (组包=基于 r_k 的纯增量) 失效；
> 补偿在 Non-IID 下方向错位且幅度大，从修正退化为系统性错误强加**。
> 属机制级冲突，不是超参问题。

推论:
- 单独机制均安全: reuse 无害无益 (Non-IID), VCM 单用略正 (IID +1.5pp, Non-IID +0.6pp)。
- reuse × VCM 的组合收益仅在 IID 成立; 强 Non-IID 下应先扣除 reuse。

## 4.5 修复尝试: 增量空间重锚定 (Delta Rebase) — 结论: 未救活

### 动机

参数空间混合 `w̄ = (1−ρ)·w_new + ρ·w_stale` 把旧锚点漂移 `W(r_stale)−W(r_k)` 注入组包。
修复思路: 改为增量空间混合, 严格锚定当前基:

```
w̃ = W(r_k) + (1−ρ)·Δ_new + ρ·Δ_stale
Δ_new = w_new − W(r_k),  Δ_stale = w_stale − W(r_stale)
```

实现: `user.py` 新增 `ours_delta` 规则 (缓存 `_p2_stale_base_flat` / `_p2_pending_base_flat`,
`p2_confirm_upload_failed`/`p2_confirm_consumed` 同步维护), `main_point2.py --reuse-rule ours_delta`。

### 安全/验证理论

验证链 (LHH 同态、Ed25519、base_hash 绑定、公开重算) 断言"传输完整性 + 聚合算术 +
基版本绑定", 从不断言"上传模型是真实训练产物"; mask 由 PRG(ta_seed, uid, token) 生成,
与明文内容无关; delta 计算纯本地 (缓存 W(r_stale) 为失败轮已传入的 global_flat),
零新消息零新 metadata → **安全模型与验证过程理论推导不变**。

### 实验 (与 G5 model-space 同 seed 直比)

| seed | model-space | delta |
|------|-------------|-------|
| 12 | 91.28 | 91.74 |
| 42 | 82.94 | 84.42 |
| 43 | 87.67 | 86.93 |
| 44 | 65.00 | **62.66** |
| 45 | 78.29 | 82.75 |
| NI 均值±σ | 81.04 ± 10.03 | **81.70 ± 11.17** |
| IID (s42) | 90.20 | 90.11 |

### 判定

- 失败判据命中: NI 均值 81.70 < 87.3 (G3 基线), std 11.17 > 4;
- IID 持平 (90.11, 理论预期: IID 下两种混合近似等价) ✅
- **根因修正**: 锚点错位不是崩溃主因; `Δ_stale` 本身 (用户历史本地增量) 在强 Non-IID 下
  与当前任务方向相悖, 叠加 VCM 每轮强加全局更新 → 组合互斥与混合空间无关。

### 最终处置

> **reuse 在强 Non-IID 下应整体关闭** (维持 §5 叙事)。delta 实现保留为 `ours_delta`
> 实验选项 (IID 安全, 可作消融展示), 不作为主协议。

## 4.6 修复尝试 2: MAFSA 忠实掉线语义 (掉线轮训练+回收) — 结论: 仍无正收益

### 动机

MAFSA 原文 (EAAI 2026) Algorithm 1: 客户端掉线时**继续在本地旧模型上训练**,
恢复上线后上报过期更新, 由 ES 以 `α·w^t + (1−α)·w^{t_i}` (α=e^{−βE}) 组合。
此前模拟的掉线 = 纯跳过, reuse 从未在"掉线算力回收"语义下被验证。

### 实现

- `user.py` 新增 `p2_train_offline_and_cache`: 掉线轮在 self.model / 已有 stale 缓存上
  继续训练并缓存 (连掉多轮成果逐轮累积); 恢复轮由 mafsa/ours 混合规则回收。
- `main_point2.py --dropout-mode {skip, offline_train}`, `--dropout-reuse rebase` 保留旧语义。
- 语义映射与 MAFSA 原文一致 (ζ~Bernoulli(pᵢ), E=t−tᵢ, stale 权重 1−α 随 E 递增)。

### 实验 (Non-IID α=0.5, 5 seeds, 全局墙钟口径)

| 方案 | d=0.3 | d=0.5 |
|------|-------|-------|
| G3 (skip) | 87.92 ± 1.85 | 85.60 ± 5.28 |
| G4m (mafsa+回收) | 87.04 ± 2.36 | 86.02 ± 5.47 |
| G5d (ours_delta+VCM+回收) | 88.18 ± 3.58 | 85.93 ± 7.32 |

同 seed 配对差 (d=0.5): G4m−G3 ∈ [−10.2, +11.5], G5d−G3 ∈ [−13.4, +12.4]
→ 无系统性方向, 方差主导。

### 判定

- **掉线语义修正后 reuse 仍无稳定正收益** (早期 2-seed "反超"为假象, 扩 seed 后消失)。
- 附带结论: VCM 在 MAFSA 语义下不崩 (85.9~88.2, 对比 upload-fail 语义 81.0±10),
  因掉线缓存的 stale 走恢复轮混合 + 重锚定路径, 与 VCM 兼容性更好; 但亦无显著正收益。

## 4.9 Tier-1 新机制: 服务器 EMA (有效, 可叠加) 与 FedProx (无效)

日期 2026-08-29。基线 = G3+VCM+σ0.5 (Non-IID α=0.5, 8 seeds {12,42,43,44,45,46,47,48})。
机制筛选按已验证的涨点边界执行: 只试"漂移修正/方差缩减"族, 不再碰动量/调度/分组族。

### 服务器端 EMA (checkpoint 级 Polyak 平均, 纯后处理)

- 实现: commit 后维护影子模型 `ema ← a·ema + (1−a)·W(t)`, 评测用 Adam 式偏差校正
  `êma = ema/(1−a^t)`; **不回灌训练、不改变下发模型**, 与掩码/验证链完全无交互
  (`main_point2.py --ema-decay a`, raw/EMA 双曲线入 npz)。
- 口径: EMA 的额外评测每次创建 DataLoader 迭代器消耗一次全局 torch RNG
  (PyTorch `_BaseDataLoaderIter` 播种行为), 故 EMA run 的 raw 轨迹与 SIG 基线存在
  RNG 流偏移 (各档 raw 逐值一致, ckp1 与基线一致 —— 不变性校验通过)。
  **EMA 净效果一律按同 run 配对 (EMA − 同run raw) 度量**。
- 结果 (同 run 配对, Non-IID 8 seeds):

| a | Δmean±std | 正/负 | EMA 均值±std |
|-----|-----------|-------|--------------|
| 0.4 | +0.96 ± 1.02 | 8/8 | 90.25 ± 1.38 |
| **0.5** | **+1.10 ± 1.25** | **8/8** | **90.38 ± 1.33** |
| **0.6** | **+1.10 ± 1.39** | 7/1 | 90.38 ± 1.33 |
| 0.8 | +0.45 ± 1.56 | 4/4 | 89.73 ± 1.46 |
| 0.9 | −1.19 ± 1.64 | 2/6 | 88.09 ± 1.43 |

- 定论: **a∈[0.5,0.6] 稳定 +1.1pp (8/8 正), 与 σ (+1.45) 同量级且完全正交, 可叠加**;
  滞后过强 (a≥0.8) 转负。端到端口径 EMA 90.38 vs SIG 基线 89.79 (+0.59, 混入 RNG 偏移噪声),
  论文报同 run 配对口径。
- 机理: EMA 压轨迹震荡 (s42 raw 走差 −3.9pp 时 EMA 拉回基线水平), 是 σ 的后处理补全:
  σ 修"组包陈旧度加权", EMA 修"已提交序列的轨迹抖动"。
- IID 消融 (5 seeds, 同 run 配对): Δmean +0.19 ± 0.36 (3/5 正, EMA 90.11±0.54)
  —— IID 轨迹本就平稳, EMA 近似恒等, **无害**; 与 σ 的 IID 代价 (−0.8pp) 不同,
  EMA 可无条件叠加进主协议。

### FedProx 近端项 (无效)

- 实现: 本地损失 + μ/2·‖w−W(r_k)‖² (`models.train_local(prox_mu)`, 纯本地项, 零消息)。
- 结果 (跨批次同 seed 配对, RNG 流一致故逐值精确): μ=0.01 → +0.01±0.03 (5/3);
  μ=0.1 → −0.00±0.09 (3/5)。**精确零效果**。
- 根因: local_epochs=1, 单 epoch 漂移量小; 且漂移已被 VCM (版本端) + σ (聚合端) 修正,
  源头近端项无剩余偏差可修。同类推论: Tier-3 SCAFFOLD (修同类漂移) 优先级下调。

### 方法论注记 (可复现性)

- CPU 多线程浮点非确定性会被 20 checkpoint 训练混沌放大 (实测多线程 final ±4pp);
  **OMP/MKL=1 单线程可逐值复现 08-28/08-29 全部基线** (90.17 等已验证)。
  后续所有批量实验强制单线程 (`run_tier1_batch.py`), 跨批次配对对比方为精确。
- 批量工具: `run_tier1_batch.py` (并行 runner, 单线程), `analyze_tier1.py` (配对分析)。

## 4.10 Tier-2: 2025 新论文模块 (FedBSS 课程化 / DPR 重置) — 均显著负增益, 排除

日期 2026-08-29。基线同 §4.9 (G3+VCM+σ0.5, NI 8 seeds)。两实现均保持 RNG 抽取次数
与基线逐值一致 → 跨批次配对精确 (`analyze_tier2.py`)。

| 模块 | 来源 | 实现 | Δmean±std | 正/负 |
|------|------|------|-----------|-------|
| FedBSS bias_asc (小偏差样本先训) | AAAI 2025, arXiv:2501.11360 单 epoch 适配 | `train_local(curriculum)` | **−11.46 ± 3.65** | 0/8 |
| FedBSS bias_desc (大偏差先训, 方向对照) | 同上 | 同上 | −2.89 ± 3.63 | 2/6 |
| DPR 重置 q=0.9 (每步重置漂移 top10% 维度) | NeurIPS 2025 适配 (自拟变体) | `train_local(dpr_q)` | **−18.43 ± 5.76** | 0/8 |
| DPR 重置 q=0.75 | 同上 | 同上 | −58.87 ± 5.71 | 0/8 |

判定与教训:

- **两个模块均明确排除, 不入主协议。** DPR 为自拟适配 (原文算法细节未能获取),
  负结果仅说明"逐步全维分位重置在本设置下是破坏性的", 不构成对原文的否定;
  但其机制空间 (用户端硬重置) 在 local_epochs=1 下本就无从发挥。
- **结构性规律 (8 次干预的边界 now 完整)**: 用户端/优化器侧干预
  (FedProx μ×2, BSS asc/desc, DPR ×2, staleness-LR, 调度/分组) 全部 ≤0;
  聚合/轨迹侧干预 (VCM +1.1~2.5, σ +1.45, EMA +1.10 8/8) 全部为正。
  本框架 local_epochs=1、每用户本地仅 ~6 个 minibatch, 用户端干预面太小且在
  Non-IID 下易放大类别偏置 (BSSasc: 低偏差样本集中于多数类, 排序反而强化偏置);
  **后续增益机制应只在聚合端/轨迹端寻找** (该结论可直接写进论文 ablation 讨论)。
- 论文素材: 用户端负结果族可作为 "为什么补偿必须在服务器侧做" 的动机实验。

## 4.11 Tier-3: σ 陈旧度度量消融 (arXiv:2603.08211) — 版本差即最优度量

日期 2026-08-29。2026 文献中唯一落在已验证涨点区 (聚合端) 的可缝点: 陈旧度度量选择。
实现 (`--staleness-metric`): version=版本差 s_k (原行为, 幂衰减); rel2=参数相对漂移
‖W(v)−W(r_k)‖/‖W(v)−W(0)‖ (exp 衰减, 云端可算零消息); wait=缓冲等待 ticks (幂衰减)。
NI 8 seeds 精确配对 vs version σ0.5 基线 (89.79±1.48):

| 度量 | 强度 | Δmean±std | 正/负 | 均值±std |
|------|------|-----------|-------|----------|
| rel2 | σ=5 | −0.93 ± 1.30 | 1/7 | 88.86±2.25 |
| rel2 | σ=15 | −1.58 ± 1.33 | 1/7 | 88.21±2.11 |
| wait | σ=0.5 | −0.94 ± 1.26 | 2/6 | 88.85±2.00 |
| wait | σ=1.0 | −0.78 ± 1.08 | 1/7 | 89.01±1.90 |

定论:

- **版本差是最优度量**: 参数距离与缓冲等待均低于 version σ (且强度越大越差)。
  机理: 三者高度相关, 但版本差是零噪声的整数信号, rel2 混入训练噪声、wait 混入
  调度噪声。
- 但四个变体全部高于无 σ 基线 (88.33±3.00) → **σ 机制对度量选择稳健**,
  "version > wait ≈ rel2 > 无 σ" 可直接作为论文中 σ 设计正当性的消融素材。
- 2026 文献聚合端可缝候选至此测试完毕, 无新增益; 增益探索正式收官
  (主协议 = G3+VCM+σ0.5+EMA a=0.5)。

## 4.12 安全验证线: 全密码学端到端 (+Tiny 模型) — 四类攻击 100% 检出, 三层纵深

日期 2026-08-30。主协议 (G3+VCM+σ0.5, α 加权路径) 下的全真 LHH (NIST P-256, 纯 Python
ecdsa) + Ed25519 端到端。全维 CNN (d=582,026) 单次 Hash 实测 ~2.8 min (串行微基准
220~307µs/维), 一次 run ~96+60 次 Hash ≈ 4.4 小时不可行 → 新增 `--model Tiny`
(d=7,850 线性分类器, 精度 88.1~88.3) 使全密码学端到端可行, 开销按实测线性外推
(与 docs/OVERHEAD_EXPERIMENT.md 分析法口径一致; 检测性质与维度无关——任一维
篡改即破坏同态等式)。

### 验证透明性 (8 seeds)

verify on/off 的 acc history **逐值一致** (88.10), 20/20 checkpoint 验证通过,
`--verify` 不改变聚合数学、不消耗 RNG、不干预 σ/VCM/EMA 路径。

### 攻击检出 (verify on, 8 seeds, α 加权 + VCM 激活)

| 攻击 | 对象 | 检出率 | 尝试 | 提交 | 说明 |
|------|------|--------|------|------|------|
| tamper_global (篡改 raw_sum) | LHH 等式 | **100%** | 56.6 | 0 | fail-closed: 60 ticks 内 0 提交 |
| tamper_manifest (注入假包) | 签名层 (先) | **100%** | 56.6 | 0 | Ed25519 快速失败, 不走 LHH (run 仅 ~5min vs ~15min) |
| drop_replace_pkg (漏聚合) | LHH 等式 | **100%** | 56.6 | 0 | 同式失败 |
| replay (重放消费过的包) | Aggregated_IDs | **100%** | 20 | 20 | buffer 层 exactly-once, 与 verify 无关, 正常提交 |

### 三层纵深防御 (verify off, 同攻击)

| 攻击 | 无验证后果 | 拦截层 |
|------|-----------|--------|
| tamper_manifest | acc=0.00, 56.6 次 guard 拒绝 | **协议层 commit guard (免密码学)** |
| replay | 20/20 拒绝, 0 接受 | **协议层 exactly-once (免密码学)** |
| tamper_global | acc=88.22 (= 基线), **静默接受** | 仅 LHH 能发现 |
| drop_replace_pkg | acc=83.58 (**−4.6pp 静默偏置**) | 仅 LHH 能发现 |

→ 两类结构级攻击 (manifest/replay) 被廉价协议守卫免费兜住; 两类数学级攻击
(tamper_global/drop_replace) 只能靠 LHH 拦, 其中漏聚合造成 −4.6pp 静默损害 —
这是"验证必须做在 checkpoint 级"的最强实证。

### 开销 (串行干净口径)

- 端到端 d=7,850: TINY 59.8s → VF 496.9s, **验证开销 437s/run ≈ 21.9s/checkpoint**
  (3 ES × 验证 + 封包哈希); 带载 4-worker 口径 35.4s/ckp。
- 微基准: LHH ~223µs/维 (median) → **外推 d=582,026 单次 Hash ≈ 130~166s**;
  Ed25519 sign 32µs / verify 138µs (每 run ~96 seals 共 4.9ms, 可忽略);
  PRG 掩码 0.02µs/维 (全维每用户 8.7ms) → **客户端 O(d) 轻量性成立,
  成本全部集中在服务器/边缘侧 LHH**, 且 TMv 案例证明签名先行使常见篡改快速失败。
- 与 2026 竞品对比素材: TDSC 2026 报验证约 200ms/epoch (C/工程化实现);
  我们报三层粒度 (sign 32µs/包 → 外推全维 LHH 2.2~2.8 min/次 → 端到端实测),
  并注明纯 Python ecdsa 是当前瓶颈, LHH 工程化 (C/预计算) 后可与竞品同量级。

## 5. 论文叙事建议

- **主协议 = G3+VCM+σ0.5 (+EMA a=0.5 后处理)**: 半异步 + Direct-VCM 组间补偿 + 陈旧度幂衰减权重
  + 服务器 EMA。Non-IID 口径: VCM +1.12 (5/8) → +σ +1.45 (5/8, std 3.0→1.5) →
  +EMA +1.10 (8/8, 同 run 配对); IID 口径: VCM +2.47 (5/5), σ 有 −0.8pp 代价 (可选消融),
  EMA 无害 (+0.19±0.36, 3/5) —— EMA 无条件叠加, σ 建议仅 Non-IID 场景启用 (或作为
  "异质场景稳健性开关" 叙事)。
- **机制三部曲叙事**: σ (聚合端陈旧度加权) → VCM (版本端漂移补偿) → EMA (轨迹端后处理平滑),
  三者正交可叠加, 全部保持掩码加性结构与单 TA 验证链不变。
- **stale reuse 整体不主推**: 全家族 (ours/mafsa/ours_delta, 上传失败/掉线回收两种语义,
  ρ ∈ {0.1,0.2,0.5}, 有无 VCM) 均无稳定正收益; 双种子早期 "反超" 已被扩 seed 证伪。
  论文中以消融对照 + 限制讨论呈现 (如实报告, 不作负面辩护)。
- 声称范围保持克制: 机制收益表按 seed 配对均值±方差呈现, 不隐藏 std、不筛选 seed。
