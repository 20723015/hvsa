# 研究点2方案稿：基于提前分组的组内同步、组间异步双辅助服务器可验证安全聚合

## 1. 推荐题目

- 题目1：基于双辅助服务器可验证安全聚合的提前分组分层半异步联邦学习方法
- 题目2：面向分层联邦学习的组内同步组间异步可验证安全聚合机制
- 题目3：兼顾验证正确性与训练时延的分组半异步安全联邦学习方案

推荐采用题目1，因为它同时体现了：

- 研究基础：双辅助服务器可验证安全聚合
- 研究策略：提前分组
- 异步形式：分层半异步

## 2. 一句话定义

本研究在研究点1的双辅助服务器可验证安全聚合框架基础上，引入基于通信时延或总完成时延的提前分组策略，使组内用户从同一全局模型出发进行同步训练与组级安全聚合，而不同组在云端以验证通过的组级结果为单位执行异步更新，从而在不破坏验证机制的前提下降低全局同步等待开销。

## 3. 为什么先做这版

与更激进的窗口化异步方案相比，这一版更适合作为研究点2的第一阶段实现，原因有三点：

1. 它和 FedFleet 的思路最接近，容易在相关工作里对齐。
2. 它保留了组内固定参与集合，更容易让双辅助服务器部分掩码和边缘验证继续成立。
3. 它对现有代码改动相对可控，不需要一步到位改成完全事件驱动的窗口系统。

需要特别强调的是，这里的“组内同步”并不意味着无限等待组内所有用户。为了保持掉线容忍性，本方案采用的是“带截止时间的组内同步聚合”：

- 同组用户从同一全局模型版本开始训练。
- 边缘服务器在预设截止时间到达后，封存本轮该组的实际在线集合。
- 只有在截止时间之前到达的用户参与本轮组级聚合。

因此，本方案本质上是：

`提前分组 + 组内定时同步 + 组间异步 + 组级验证`

## 4. 系统模型

### 4.1 系统角色

- 用户 `u_i`：在本地数据上训练模型并上传掩码后的模型参数。
- 边缘服务器 `e_g`：对应一个组，负责组内用户收集、组级预聚合和组级验证证据生成。
- 云服务器 `C`：接收各组已完成的安全聚合结果，在验证通过后执行异步全局更新。
- 辅助服务器 `A1` 与 `A2`：分别持有独立的种子材料，对同一组同一轮的实际在线集合独立计算部分掩码和掩码证据。

### 4.2 分组方式

设系统共有 `N` 个用户、`G` 个边缘组。初始化阶段，系统根据每个用户的时延画像进行提前分组。

如果实验中只能测得通信时延，则定义用户画像为：

`d_i = t_i^comm`

如果可以同时统计本地训练时间与上传时间，则更推荐定义为：

`d_i = t_i^train + t_i^comm`

随后按照 `d_i` 从小到大排序，并将用户划分为 `G` 个组，每组映射到一个边缘服务器。这样做的目标是使同组用户的完成时间尽量接近，从而减小组内同步等待时间。

### 4.3 组与轮次

设第 `g` 个组在第 `r` 轮的用户集合为 `U_g`。在本轮开始时，云端广播当前全局模型 `W^r` 给所有组。每个组都从同一个全局模型 `W^r` 出发进行本地训练。

组 `g` 在第 `r` 轮的实际在线用户集合记为：

`S_g^r subseteq U_g`

其中 `S_g^r` 由截止时间之前成功上传的用户组成。后续的部分掩码生成、解掩码和验证，全部绑定到 `S_g^r` 上进行。

## 5. 威胁模型与设计要求

本方案继承研究点1的基本威胁模型：

- `A1` 与 `A2` 为两个独立的非串通逻辑辅助服务器。
- 云服务器可能是恶意的，可能尝试篡改、伪造或选择性丢弃聚合结果。
- 边缘服务器默认诚实但好奇，负责执行验证。
- 用户可能掉线，但不假设大规模主动恶意篡改。

在该威胁模型下，研究点2必须满足以下要求：

1. 用户仍只上传一个掩码模型参数向量，不能引入额外用户侧复杂协议。
2. 两个辅助服务器必须基于相同的组标识、轮次和实际在线集合 `S_g^r` 计算部分掩码。
3. 云端必须在组级验证通过后，才能将该组结果写入全局模型。
4. 异步的最小更新单元必须是“组级聚合结果”，而不是单个用户。

## 6. 协议流程

### 6.1 初始化与提前分组

系统在初始化阶段测量每个用户的时延画像 `d_i`，按时延大小规律排序后划分用户组：

`U_1, U_2, ..., U_G`

每个组绑定一个边缘服务器 `e_g`。这一过程在训练开始前完成，训练期间可以保持静态分组；如果后续实验需要，也可以扩展为周期性重分组，但这不是第一阶段必须实现的内容。

### 6.2 全局模型广播

在第 `r` 轮开始时，云服务器广播当前全局模型 `W^r`。组 `g` 内所有用户都基于同一个全局版本进行本地训练。

这一步非常重要，因为它保证同组聚合结果具有一致的基模型来源，从而使组级验证和组级异步更新都更容易成立。

### 6.3 用户本地训练与掩码上传

用户 `u_i` 在本地训练完成后，得到模型参数 `w_i^{g,r}`。两个辅助服务器分别为其提供掩码成分：

`m_i^(1)(g,r)` 和 `m_i^(2)(g,r)`

用户上传一个掩码后的模型参数向量：

`wbar_i^{g,r} = w_i^{g,r} + m_i^(1)(g,r) + m_i^(2)(g,r)`

这里继续沿用当前仓库的设计，即上传和聚合的是模型参数，而不是单步梯度。

### 6.4 组内定时同步聚合

组 `g` 对应的边缘服务器 `e_g` 在本轮维护一个组级截止时间 `tau_g^r`。在截止时间到达前，边缘服务器持续接收组内用户上传；到达截止时间后，边缘服务器封存本轮实际在线集合：

`S_g^r = {u_i in U_g | u_i before tau_g^r uploads successfully}`

随后计算组级掩码和：

`Wbar_g^r = sum_{u_i in S_g^r} wbar_i^{g,r}`

并生成组级验证证据：

- `H_masked(g,r) = LHH(Wbar_g^r)`
- `Sig_g^r = Sign(H_masked(g,r), g, r, |S_g^r|)`

需要注意的是，这里不是等 `U_g` 中所有用户无穷等待完成，而是在同一轮、同一基模型下，对“截止时间前到达的实际在线用户集合”进行同步聚合。这样才能同时保留掉线容忍和组级验证。

### 6.5 双辅助服务器组级部分解掩码

边缘服务器将本轮组 `g` 的实际在线集合 `S_g^r` 发送给两个辅助服务器。随后：

`A1` 计算：

`M_{g,1}^r = sum_{u_i in S_g^r} m_i^(1)(g,r)`

`A2` 计算：

`M_{g,2}^r = sum_{u_i in S_g^r} m_i^(2)(g,r)`

同时，两个辅助服务器分别生成部分掩码哈希：

`H_mask^(1)(g,r) = LHH(M_{g,1}^r)`

`H_mask^(2)(g,r) = LHH(M_{g,2}^r)`

这一步把当前研究点1中的“整轮全局部分掩码”改成了“组级部分掩码”，是本研究点2最关键的结构变化。

### 6.6 云端恢复组级明文聚合结果

云端在收到组 `g` 的组级掩码和及两份部分掩码后，恢复该组的明文聚合结果：

`W_g^r = Wbar_g^r - M_{g,1}^r - M_{g,2}^r`

并进一步得到该组的平均模型参数：

`Wtilde_g^r = W_g^r / |S_g^r|`

这里的 `Wtilde_g^r` 是后续组间异步更新的最小提交单元。

### 6.7 组级验证

为了保证研究点1中的验证机制不失效，本方案要求每个组在写入全局模型前都必须完成组级验证。验证关系定义为：

`H_plain(g,r) + H_mask^(1)(g,r) + H_mask^(2)(g,r) = H_masked(g,r)`

其中：

- `H_plain(g,r) = LHH(W_g^r)`
- `H_masked(g,r)` 为边缘服务器对组级掩码和的哈希
- `H_mask^(1)(g,r)` 与 `H_mask^(2)(g,r)` 分别由 `A1`、`A2` 提供

这一定义与当前代码中的整轮验证关系一一对应，只是把验证对象从“全局整轮聚合结果”下沉到“单个组的聚合结果”。这样一来，云端即使采用异步更新，也无法绕过验证直接伪造组级结果。

### 6.8 组间异步更新

与研究点1的整轮同步更新不同，在本方案中，云端不再等待所有组都完成本轮聚合后再统一更新，而是采用“验证通过即提交”的异步机制。

设组 `g` 的结果在当前全局版本 `v_current` 时到达，其基模型版本为 `r`，则其陈旧度定义为：

`s_g^r = v_current - r`

为减轻陈旧组更新对全局模型的负面影响，引入陈旧度感知权重：

`lambda_g^r = lambda_0 / (1 + s_g^r)`

云端执行异步融合：

`W^{v_current+1} = (1 - lambda_g^r) W^{v_current} + lambda_g^r Wtilde_g^r`

只有当该组的验证通过时，才允许执行上述更新。若验证失败或陈旧度超过阈值，则该组结果被拒绝。

## 7. 与现有系统的对比

### 7.1 现有研究点1

当前研究点1的同步模式可以概括为：

1. 所有用户在全局轮 `r` 上训练并上传。
2. 每个边缘服务器聚合本轮收到的所有本地上传。
3. 两个辅助服务器汇总所有边缘上报的在线用户集合，计算整轮全局部分掩码。
4. 云端等待所有边缘结果和两份部分掩码到齐。
5. 云端恢复整轮全局明文结果。
6. 边缘服务器执行整轮验证。
7. 验证通过后更新全局模型。

它的优点是结构清楚、容易证明；缺点是所有组彼此等待，训练时延受最慢组拖累明显。

### 7.2 本研究点2方案

本研究点2的分组半异步模式则是：

1. 初始化时先按时延画像对用户提前分组。
2. 同组用户从同一全局版本开始训练。
3. 组内在截止时间处进行同步聚合，得到本轮实际在线集合 `S_g^r`。
4. 两个辅助服务器对该组该轮的 `S_g^r` 计算组级部分掩码。
5. 云端恢复该组明文平均模型。
6. 先完成组级验证，再异步写入全局模型。
7. 不同组不再彼此等待。

因此，它解决的核心问题不是“消除组内等待”，而是“消除组与组之间的全局 barrier”。

## 8. 论文里可直接使用的系统模型描述

下面这段可以直接作为论文正文初稿：

“考虑一个由云服务器、多个边缘服务器、终端用户以及两个非串通辅助服务器构成的分层联邦学习系统。系统在训练开始前根据用户的通信时延或总完成时延画像对用户进行提前分组，并将每个用户组映射到一个边缘服务器。第 `g` 个组在第 `r` 轮从相同的全局模型 `W^r` 出发执行本地训练，边缘服务器在预设截止时间到达后封存该组本轮的实际在线用户集合 `S_g^r`，并基于 `S_g^r` 完成组级掩码聚合。两个辅助服务器分别针对相同的 `S_g^r` 计算组级部分掩码，云服务器在恢复组级明文聚合结果并通过组级验证后，将该组结果以异步方式写入全局模型。由此，系统在保持双辅助服务器安全聚合与边缘侧可验证性的前提下，实现了组间异步更新。” 

## 9. 论文里可直接使用的创新点描述

1. 提出一种基于时延感知提前分组的分层半异步联邦学习机制，使双辅助服务器可验证安全聚合框架能够从整轮同步扩展到组间异步更新。
2. 设计组级部分解掩码机制，将研究点1中的整轮全局部分掩码细化为组级部分掩码，使每个组都形成独立的可解掩码、可验证闭环。
3. 构建组级验证机制，在异步更新场景下仍能保证云端无法绕过验证直接伪造或篡改组聚合结果。
4. 通过时延感知分组减少组内性能差异，通过组间异步提交消除全局 barrier，从而降低训练等待开销。

## 10. 实验设计

### 10.1 对比方法

| 方法 | 分组方式 | 组内方式 | 组间方式 | 验证粒度 |
|---|---|---|---|---|
| 同步 HVSA | 无提前分组 | 整轮同步 | 整轮同步 | 整轮验证 |
| 本方案 | 时延感知提前分组 | 组内定时同步 | 组间异步 | 组级验证 |
| FedAvg / HFL 基线 | 可无 | 组内同步 | 多数为组间同步 | 无安全验证 |

### 10.2 实验指标

建议至少汇报以下指标：

- 达到目标精度所需训练时间
- 相同墙钟时间下的测试精度
- 每轮平均等待时间
- 最慢组造成的同步阻塞时间
- 组级验证通过率
- 平均陈旧度
- 通信开销与密码开销

### 10.3 消融实验

建议做三组消融：

1. 是否提前分组：
   - 随机分组
   - 按通信时延分组
   - 按总完成时延分组

2. 是否组间异步：
   - 分组但组间同步
   - 分组且组间异步

3. 是否开启验证：
   - 无验证
   - 整轮验证
   - 组级验证

## 12. 实现建议

如果按当前仓库来改，建议的最小实现路径如下：

1. 保留用户上传一个掩码参数向量的基本结构。
2. 在初始化阶段引入用户分组逻辑，替代当前按编号静态绑定边缘服务器的方式。
3. 将 `TA1/A2` 的部分掩码计算从“整轮全局在线集合”改为“组 `g` 在轮 `r` 的实际在线集合 `S_g^r`”。
4. 将当前整轮验证改造成组级验证。
5. 云端从“等所有组到齐再统一更新”改为“验证通过的组先提交先更新”。

这条路线比直接改成窗口化完全半异步更稳，更适合先把研究点2做实。

## 13. 一句话总结

这版研究点2最稳的落地方式不是“所有层面都异步”，而是“提前分组后组内定时同步聚合、组间验证后异步更新”。它既保住了双辅助服务器安全聚合和边缘验证，又能清楚地体现相对于研究点1的时延优化价值。
