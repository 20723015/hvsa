# 研究点二：基于 checkpoint 更新矩的版本补偿设计

日期：2026-10-12。状态：**用户已选择的研究路线；数学与协议设计稿，尚未接入训练和完整安全实现，未确认效果或独立新颖性。**

本稿取代 2026-10-11 三日计划中“客户端维护范数矩、再汇总到组”的候选路线。研究点二名称仍为“基于版本补偿的半异步分层可验证安全聚合方法”。本次具体机制称为 **checkpoint 更新矩校准**，不称为客户端矩的组级等价适配。

## 1. 约束、职责与设计范围

- 客户端沿用原有本地训练、样本量加权、量化、掩码上传；不新增范数计算、矩状态、统计上报或确认矩状态的消息。
- TA 继续只释放冻结 checkpoint 的总掩码，不增加单组解掩，不向边缘释放个人掩码或组掩码。
- 边缘从已验证 checkpoint 总和及共识模型历史，计算整体更新范数、维护历史矩、重构下一模型并核验状态转移。
- 云端可以计算候选作为工程辅助，但不能决定统计、系数或下一共识模型。边缘必须独立复算。
- 保留现有调度作为固定实验背景；本机制不额外优化选组、等待时间、组权重或本地训练。

“客户端不变”以原本只训练、掩码上传的基线职责为准。当前实验代码 `user.py` 已存在 `_p2_last_upd_norm`，`main_point2.py` 将其送往边缘；新模式不得读取或依赖这条实验旁路，正式接入时应在新模式中关闭该计算与传递。客户端已有的其他功能不属于本设计新增要求。

“只在边缘新增算法工作”不等于只修改 `edge.py`：配置、候选消息、投票结果摘要和提交恢复记录还需同步支持新状态。TA 的掩码释放语义不变，但提交记录需绑定矩状态摘要。

## 2. 边缘实际能够获得的更新

令当前共识模型为 \(W_t\)，冻结的选中组包集合为 \(Q_t\)。组内共用基版本 \(r_k\)，实际样本量为 \(S_k>0\)，定义

\[
S_t=\sum_{k\in Q_t}S_k,\qquad p_k=S_k/S_t.
\]

\(U_k\) 表示组内样本量加权的训练终点模型，仅用于数学描述；**协议不要求任何边缘得到单个 \(U_k\)**。暂忽略量化，边缘验证总和后得到

\[
R_t=\sum_{k\in Q_t}p_kU_k,\qquad
A_t=\sum_{k\in Q_t}p_kW_{r_k}.
\]

定义

\[
\boxed{\Delta_t=R_t-A_t},\qquad D_t=W_t-A_t,\qquad
u_t=\|\Delta_t\|_2,\quad d_t=\|D_t\|_2.
\]

因此

\[
\Delta_t=\sum_{k\in Q_t}p_k(U_k-W_{r_k}).
\]

\(\Delta_t\) 是本次 checkpoint 的平均训练增量；\(D_t\) 是当前模型与所选基模型平均值之间的版本差。前者尚未加入本次补偿，避免将补偿后的位移误当作训练输入。

### 2.1 编码语义

现有上传为 \(q_i=\operatorname{Quantize}(n_iU_i)\) 再加掩码。记已验证整数总和为 \(Z_t\)，量化尺度为 \(F\)。实施时使用

\[
R_t^{\rm enc}=Z_t/(F S_t),\qquad
\Delta_t^{\rm enc}=R_t^{\rm enc}-A_t.
\]

下文所有范数与模型计算均使用这条编码语义。它等于理想平均增量加量化误差，不能称为精确恢复未量化的本地增量。与“逐客户端先算增量再量化”的路径比较时需单独计量量化次序差异；相同整数输入下，量化明文与安全路径应一致。

首版仅采用样本量权重；不叠加 V-PDA、额外陈旧度聚合权重或客户端缓存。扩展权重时必须同时统一 \(R_t,A_t\) 的权重和分母，不能只改一侧。

## 3. 一阶矩、系数与确定性回退

### 3.1 提交前状态与本次候选

每个核验边缘持有同一份已提交状态

\[
\mathcal S_t=(c_t,m_t,g_t,h_t),\qquad c_0=m_0=g_0=0.
\]

\(c_t\) 计成功提交的 checkpoint 数；\(m_t\) 是以零初始化的 checkpoint 训练增量范数 EMA；\(g_t\) 是以零初始化的实际共识模型位移范数 EMA；\(h_t\) 是该已提交状态记录的摘要，记录中包含父状态摘要而不包含自己的摘要，避免循环定义。初始状态记录绑定 run、初始模型及配置摘要。首版从版本 0 启用，全程同一配置，故正常执行时 \(c_t=t\)。中途切换模式需另行迁移，不能静默重置矩。

先计算暂存值

\[
m_t^*=\beta m_t+(1-\beta)u_t,\qquad
\widehat m_t^*=\frac{m_t^*}{1-\beta^{c_t+1}}.
\]

当 \(c_t>0\) 时，历史全局尺度为

\[
\widehat g_t=\frac{g_t}{1-\beta^{c_t}}.
\]

**分子含本次已验证输入，分母只含此前已提交的模型位移。** 不使用尚未算出的 \(W_{t+1}\) 更新分母后再求本次系数。

### 3.2 矩比例候选

首版建议参数为 \(\beta=0.9\)、\(\epsilon=10^{-12}\)、\(\rho_{\min}=0\)、\(\rho_{\max}=2\)。这是开发起点，不是已验证最优参数。固定基础对齐系数为 1，不另外叠加可调 \(\gamma\)。

\[
\bar\rho_t=
\begin{cases}
1,&c_t=0\ \text{或}\ \widehat g_t\le\epsilon\ \text{或}\ d_t\le\epsilon,\\
\operatorname{clip}\!\left(\widehat m_t^*/(\widehat g_t+\epsilon),0,2\right),&\text{其他情况}.
\end{cases}
\]

这是一条可复算的尺度启发式：比较本次平滑训练增量与既往实际模型位移，生成整个 checkpoint 共用的比例。它不能识别各组的训练强度或更新方向，也没有继承 DVAFL 的客户端统计定义及收敛结论。

### 3.3 对基础对齐的额外偏移限幅

由代数可得

\[
R_t+\rho_tD_t
=W_t+\Delta_t+(\rho_t-1)D_t.
\]

因此 \(\rho_t<1\) 会引入指向旧基点的偏移，并非天然更加稳定。当各组增量相互抵消、\(u_t\) 很小而 \(d_t\) 很大时，仅将比例截断到 \([0,2]\) 仍不够。

首版增加一个公开的残差上限，建议 \(\kappa=0.5\)：

\[
e_t=|\bar\rho_t-1|d_t,\qquad
\eta_t=
\begin{cases}
1,&e_t=0,\\
\min(1,\kappa u_t/e_t),&e_t>0,
\end{cases}
\qquad
\rho_t=1+\eta_t(\bar\rho_t-1).
\]

最终模型按下式重构：

\[
\boxed{W_{t+1}=W_t+\Delta_t+(\rho_t-1)D_t
       =R_t+\rho_t(W_t-A_t)}.
\]

限幅约束的是相对基础对齐的**新增残差**，不是把原本完整的版本对齐项压到零。精确算术下有

\[
\|W_{t+1}-(W_t+\Delta_t)\|_2\le\kappa\|\Delta_t\|_2.
\]

由三角不等式与 Cauchy–Schwarz，\(0\le\kappa<1\) 时还有

\[
(1-\kappa)u_t\le\|W_{t+1}-W_t\|_2\le(1+\kappa)u_t,
\]
\[
\langle W_{t+1}-W_t,\Delta_t\rangle\ge(1-\kappa)u_t^2.
\]

这些仅约束与已聚合训练增量的几何关系。陈旧的 \(\Delta_t\) 仍可能是坏方向，因此不是损失下降或收敛保证。浮点验证应报告舍入容差。

### 3.4 下一矩状态

先得到最终候选模型，再计算

\[
z_t=\|W_{t+1}-W_t\|_2,\qquad
g_t^*=\beta g_t+(1-\beta)z_t.
\]

候选下一状态为 \((c_t+1,m_t^*,g_t^*,h_{t+1})\)。只有 TA finalize 成功才成为已提交状态。计数、两种矩及模型必须在同一逻辑提交事件下推进。

### 3.5 必须成立的边界

| 情况 | 明确行为 |
|---|---|
| 首次提交或历史分母近零 | 系数回退为 1，本次矩仍正常暂存并随提交推进 |
| 所有组都基于当前版本 | \(A_t=W_t\)，补偿差为零，退化为本次训练终点平均 |
| 仅加权基点恰好等于当前模型 | 同样不产生额外版本偏移；不推出所有组都新鲜 |
| \(u_t=0\) | 最终残差为零，\(W_{t+1}=W_t\)，防止无训练增量时退回旧模型 |
| \(\bar\rho_t=1\) 或 \(\kappa=0\) | 等价于基础增量聚合 |
| 非有限输入/矩、非法权重、缺失基版本、维数错配 | 拒绝候选，不用回退掩盖输入错误 |
| 失败、过期或重复提交通知 | 不重复推进矩；确认已提交的状态不得因通知丢失而回滚 |

本次统计是 \(\|\sum_kp_k\Delta_k\|\)，通常不等于 \(\sum_kp_k\|\Delta_k\|\)，更不等于客户端历史范数矩加权平均。组方向抵消属于统计对象的固有限制。

## 4. 消息流程与状态机

1. **客户端上传与边缘封包：**沿用原协议，组包绑定 token、实际参与集合、基版本/摘要、样本量、掩码和证据。新模式不包含客户端范数统计。
2. **冻结并解掩：**沿用已选调度规则冻结 \(Q_t\)，TA 只为该决策提供 checkpoint 总掩码；沿用 token 和重复查询约束。
3. **验证输入：**边缘核对配置、共识版本、组包签名、基模型摘要、实际样本量及 LHH 聚合关系。通过后才将整数总和用作矩输入。
4. **独立重构：**边缘用本地已提交 \(\mathcal S_t\) 和模型历史，依次计算 \(R_t,A_t,\Delta_t,m_t^*,\rho_t,W_{t+1},g_t^*\)。不采信云端下发的前态。
5. **暂存与投票：**边缘保存候选模型和下一矩状态，为绑定全部转移的结果摘要投票。候选仅暂存，不改已提交计数或 EMA。
6. **授权和 finalize：**TA 验证所需投票及原有提交条件，将模型摘要、前后矩状态摘要、token 消费和版本联合落地。TA 不负责验证浮点补偿算法，只承接边缘核验结果及前态连续性。
7. **幂等发布：**云端及边缘依据已 finalize 的凭证发布对应模型与矩状态。丢失通知时查询凭证并补齐状态；重放同一提交只确认，不再次计算递推。

| 事件 | 模型与矩的处理 |
|---|---|
| 收到组包、完成解掩或完成验证 | 已提交状态不变；至多生成候选 |
| 验证失败或 finalize 前明确终止 | 丢弃候选；原有解掩查询限制继续生效 |
| TA finalize 成功 | 模型、矩、计数和 token 同时逻辑生效 |
| finalize 后发布失败 | 从同一凭证恢复；不得另选集或回滚矩 |
| 同一版本出现冲突结果/前态摘要 | 拒绝，不覆盖已提交或已冻结记录 |

首版每个版本仅允许一个已冻结决策。失败后的重试必须使用同一已授权输入与前态；不能以矩试验为理由反复释放不同子集或不同权重的总和。

## 5. 新增核验对象和数值规约

配置摘要至少包括：模式版本、统计定义、\(\beta,\epsilon,\rho_{\min},\rho_{\max},\kappa\)、冷启动规则、量化尺度、数值格式及提交计数事件。既有调度配置仍由原机制绑定。

矩状态记录包含 `run_id, version, count, m, g, parent_state_digest, config_digest`。边缘独立验证转移，状态哈希仅负责绑定，不能代替复算。

扩展结果摘要应绑定：当前版本与冻结 token 集合、组包/基模型/权重清单摘要、整数总和与 TA 掩码证据摘要、配置摘要、前态摘要、规范系数记录、下一模型摘要及下一矩状态摘要。投票、receipt 和持久化 journal 指向同一个扩展结果摘要。当前 `result_digest()` 仅绑定 raw sum、mask、model 等字段，不能直接称已完成矩状态联合绑定。

同一批输入必须得到同一模型与状态：

- 首版固定组包按 token 排序，固定向量维度次序；\(A_t\) 先顺序累加 \(S_kW_{r_k}\) 再除以 \(S_t\)。\(R_t\) 固定先除量化尺度，再除样本量。
- 浮点原型采用明确的 IEEE 754 binary64、最近偶数舍入，固定运算次序，不融合乘加；范数按固定次序平方求和再开方，不依赖不固定归约顺序的并行 BLAS。
- `beta^c` 采用固定次序的重复乘法；统一计算分支。所有有限性检查在哈希与投票之前完成。
- 哈希输入采用带 schema/domain 的规范字节序列；浮点为 little-endian binary64，负零规范化为正零，数组绑定形状与 dtype。不得仅靠默认字符串化。
- 正式实现若采用不同设备或高性能归约，需完成确定性数值后端及跨实现对拍后再扩大部署。不能仅靠 `np.allclose` 接受不同前态，然后期望状态摘要自然一致。

这些是待实现的数值契约；本次数学小检查只验证恒等式、边界、候选计算不修改输入前态及同输入重算一致，不覆盖实际提交状态机，也不宣称已经实现跨设备逐位共识。

## 6. 隐私、真实性与新颖性边界

在固定的已释放 checkpoint 总和及公开历史给定后，\(\Delta_t,u_t,m_t,g_t,\rho_t\) 均是边缘可复算的确定性函数。此路线不需要额外揭示单客户端统计或单组模型，不改变原有解掩集合。

这只说明相对于相同释放记录，没有新增独立的个人统计输入。新算法会改变后续训练轨迹；不能由此宣称差分隐私或跨轮泄露为零。继续沿用可信且不合谋 TA、理想信道、诚实训练等原边界；LHH 不证明客户端训练正确。

已有 `cloud.py` / `edge.py` 的 UR-VCM (`trust`) 分支已经计算 \(R_t-A_t\) 并用范数缩放补偿。因此“首次从 checkpoint 总和取得增量”不构成本方案的新增贡献。旧 `trust` 限制完整补偿 \(\eta D_t\)；本稿限制相对基础对齐的残差 \((\rho_t-1)D_t\)，并新增提交事件驱动的双 EMA、偏差校正和联合状态核验。差异可验证，但是否足以形成独立创新仍需近邻比较。

旧实验矩模式和幅度控制已出现不稳定或负面结果，不能改名后忽略；见 `POINT2_MATRIX_FINDINGS.md`。这些结果不直接等于本新统计定义的结果，也不支持预告新方法会提高准确率。

安全聚合通常只提供约定聚合量；本设计选择该可见量作为统计对象。[Bonawitz 等，安全聚合定义](https://research.google/pubs/practical-secure-aggregation-for-federated-learning-on-user-held-data/)。DVAFL 仅作为矩比例思想的参考，新规约不声称是其原算法复现。

## 7. 核验必要性与反例

固定合法 \(Q_t,Z_t,A_t,W_t\)。若云端替换历史矩或计数，使有效系数从 \(\rho_t\) 变为 \(\rho_t'\)，则模型差为

\[
W_{t+1}'-W_{t+1}=(\rho_t'-\rho_t)D_t.
\]

只要系数确实改变且 \(D_t\ne0\)，差异非零，而整数总和和 LHH 关系不变。若截断使两个系数恰好相同，本轮模型可以不变，但错误的下一矩状态仍必须拒绝，不能只比较当前模型。

一维示意：\(W_t=10,A_t=8,R_t=9\)，因此 \(\Delta_t=1,D_t=2\)。基础对齐给 11；候选矩比例为 0.5 时，\(\kappa=0.5\) 将最终系数限制到 0.75，模型为 10.5。错误历史若令最终系数变为 1.25，模型变为 11.5。两次使用的原始聚合均值仍是 9。

验证矩阵至少覆盖：重放旧矩、替换计数、替换量化尺度/分母、改变配置/回退分支、正确总和配错误模型、正确模型配错误下一矩、首次提交、零更新、全部新鲜、范数抵消、失败重试、重复 finalize/通知、finalize 后恢复。故意篡改方应能重新计算普通摘要；攻击仍应被可信前态和独立转移复算拒绝。

## 8. 实施范围与验收顺序

### 8.1 代码入口（后续实现）

| 入口 | 需要的改动 |
|---|---|
| 新增纯数学模块 | 以已验证整数总和、组元数据、共识历史和已提交矩为输入，输出候选模型/状态；无外部副作用 |
| `edge.py` | 独立调用重构、核验前后状态并暂存；finalize 后推进矩 |
| `cloud.py` | 仅候选副本及发布；旧矩分支不得自动代替新模式 |
| `point2_types.py` | 新模式配置、矩状态结构及扩展结果摘要 |
| `ta.py` / `commit_tx.py` | 沿用总掩码；扩展已验证状态摘要连续性、联合落地及恢复 |
| `main_point2.py` / `user.py` | 新模式关闭旧范数计算与传递旁路；保持训练、加权和掩码上传语义 |
| 明文参考与实验脚本 | 与编码语义逐 checkpoint 对拍；记录系数、矩、分支和提交状态 |

本稿及参数文件不是可直接传入现有 CLI 的配置。当前训练代码尚不支持该模式，不应运行旧 `moment1` 后将结果命名为本设计。

### 8.2 必要对照

1. 基础对齐 \(\rho=1\) 与显式平均增量：排除基线和版本语义错误。
2. 本方法、固定 \(\rho\) 配同一残差限幅、仅当前范数比例配同一限幅：区分动态历史矩与普通系数调整的作用。
3. 有/无残差限幅：检查收益是否仅来自限幅；另报告旧 UR-VCM `trust`，不混为同一方法。
4. 独立公式参考、同编码明文、安全实现：比较完整轨迹的模型、矩、计数和提交摘要。
5. 状态攻击与正常/恢复用例：分别报告拒绝、误拒和状态一致性；不能用训练效果代替协议验收。

先完成解析边界与小规模明文对拍，再用固定开发种子筛选。开发参数冻结后使用未调参种子；运行每种方法自己的训练动态。报告相同资源预算与实际 SGD 工作量、过期/丢弃量、最终准确率/曲线、系数截断频率和各角色成本。不能仅按 checkpoint 数宣布效率收益。

核心状态额外为每边缘两个标量 EMA、计数和摘要，活动暂存状态也为常数级；复算向量工作为 \(O(|Q_t|d)\)，多数基模型累加可复用已有对齐流程。历史模型、审计日志、恢复存档并非常数存储。客户端无新增统计通信；系统仍新增摘要绑定与状态记录成本。

阶段退出条件：若相对基础对齐没有稳定收益，或固定系数/当前尺度即可解释收益，应收缩“历史矩改善训练”的主张；新增状态哈希数量不能代替创新证明。

## 9. 中期汇报用语

主屏保留三式：

\[
\Delta_t=R_t-\sum_kp_kW_{r_k},\qquad
\rho_t=\operatorname{Calibrate}(\|\Delta_t\|,\mathcal S_t),\qquad
W_{t+1}=R_t+\rho_t\left(W_t-\sum_kp_kW_{r_k}\right).
\]

Calibrate 的具体 EMA、回退和残差上限见第 3 节，不把它作为未定义的黑盒算法。
