## 2. 最高优先级：Direct-VCM 的默认形式是增量聚合的等价表达

论文第 4 章采用组包结果均值 `w̄_k`、训练基版本 `W(r_k)`、样本量归一化权重 `p_k=S_k/ΣS_k`。令该组本地增量为：

\[
\Delta_k=\bar w_k-W(r_k).
\]

在主方法 `gamma_vcm=1`、无可选衰减的条件下，原式严格化简为：

\[
\begin{aligned}
W(t+1)
&=\sum_kp_k\left[\bar w_k+W(t)-W(r_k)\right]\\
&=W(t)+\sum_kp_k\Delta_k.
\end{aligned}
\]

这就是把各客户端/组从其训练基版本产生的增量应用到当前模型。该代数恒等式不要求 IID 或一步 SGD；具体编码舍入误差应另行界定。它也不表示“整个协议等于 FedBuff”：分层结构、触发调度、样本权重和密码学流程仍然不同。

**研究含义：G3v 相比 G3 的收益，首先说明跨版本情况下平均完整旧模型会混入旧基点，而增量聚合避免了这一问题。它尚不能证明提出了优于标准增量聚合的新补偿算法。**

标量例：当前模型为 10，两个组分别从基点 8、10 训练到 9、11。直接平均完整模型得到 10；Direct-VCM 得到 11；当前模型加平均增量也得到 11。

基点被对齐后，`Δ_k` 仍在旧模型上计算，梯度陈旧与参与偏差依然存在。因此不宜将主方法描述为已经消除 Non-IID、梯度陈旧或客户端漂移。

建议将 Direct-VCM 改定位为“与增量聚合等价的跨版本重构方式”或“基版本对齐组件”，把等价关系正式写入论文。安全聚合兼容的实现位置有工程与协议价值，但不能把代数重参数化单独包装成主要算法创新。

## 3. FedBuff 基线需要先修正，后补跑

[plain_bench.py:91](E:/hvsa/plain_bench.py:91) 的 `fedbuff_aggregate` 对完整 `u.flat` 求加权平均；[适配记录](E:/hvsa/docs/PLAIN_BENCH_ADAPTATIONS.md) 声称完整模型平均与增量平均等价。异步、不同基版本的情况下，这个等价声明不成立，缺失项恰好是上一节的基点对齐。

FedBuff 原论文 Algorithm 1–2 中，客户端发送训练前后模型之差，服务端将缓冲增量应用到当前模型；其符号方向与本文定义的 `Δ` 相反，但更新语义一致。原文同时明确其与安全聚合兼容，现有比较矩阵将“安全聚合”简单标为 × 也应修正。[FedBuff 原论文，第 4 页算法](https://proceedings.mlr.press/v151/nguyen22b/nguyen22b.pdf)

优先修正：

1. 用正确的客户端增量和服务端更新实现 FedBuff；区分版本陈旧与“到达缓冲区后的等待”，二者不能直接互换。
2. 增加一个决定性内部对照：保持当前 G3v 的组包、参与集合、触发器和权重不变，只改为显式增量聚合。该对照预期应与默认 Direct-VCM 在允许数值误差内相同。它是核查算法语义的对照，不是用来追求涨点。
3. 将 MAFSA/DVAFL 的机制移植与完整方法复现区分。取消分层周期或 DWP 后，只能回答该组件在统一触发框架中的表现，不能把结果当作完整原方法被击败。
4. 对外部基线与主方法使用相同调参预算及验证集规则；“超参沿用本文设置”本身不证明公平。

截至本次检查，`results_plain_bench/thesis_core_manifest.jsonl` 共 90 条：**22 条成功，68 条非零退出**。成功项全部来自名为 fedbuff 的现有实现：MNIST 两种分布各 5，FashionMNIST 两种分布各 5，CIFAR10 IID 2。MAFSA、DVAFL 均无成功记录。90 个目录不等于 90 个完成实验。

可以写：给定当前模拟设置，半异步加基版本对齐在三个 IID 条件下改善等时间精度；Non-IID 下未观察到统计明确的优势。不宜写“全面改善异构数据”“普遍加速收敛”“优于标准 FedBuff”。

同样不能依据“相同 20 checkpoints 下精度低于同步”直接否定点二：本次核算 G2 平均采纳 362.4 次客户端更新，G3/G3v 仅 218.2 次，预算并不相等。反过来，20 个 checkpoint 更快也不等于更快达到同一目标精度。

另有两个具体证据缺口：

- **verify-off 与端到端效率**：主矩阵关闭 LHH 验证；其调度 tick 没有直接证明完整安全协议的墙钟收益。`results_p0_verify_pair/` 本次仅见日志停在第二个 checkpoint 的候选选择，没有完整 NPZ 或对拍判定。需补齐对拍，并把训练、通信、TA 求掩码、LHH 计算及验证的关键路径成本纳入效率评价。验证 on/off 对拍也不自动证明“掩码量化轨迹等于未经量化的明文轨迹”，后者需单独比较。
- **聚合数据与论文数字一致性**：当前 NPZ 中 G2 五种子的最终 tick 为 `[100,100,124,126,120]`，G3v 为 `[51,51,54,81,48]`，均值分别为 114 和 57。论文中概括性的“100/51”不能当作完整五种子均值，必须注明单种子或重算。各时间量均为模拟时间。

建议同时报告：等模拟/端到端时间精度、等实际训练工作量精度、达到预定目标精度的时间与成功比例。采纳更新数反映有效贡献，不等于总计算量；还应记录执行的本地 SGD 步数或样本访问数、掉线和过期浪费。所有比较必须在各臂都有数据的共同预算区间内；未跑到 400 更新的臂不能用末值延伸成 400 更新结果。

## 6. 推荐的点二重构方式

建议题目：**面向异构分层联邦学习的策略绑定可验证半异步聚合方法**。

建议中心问题：**在客户端仅上传一次掩码结果、云端不可信的条件下，如何异步接纳不同基版本的组包，并验证选中集合上的聚合、公开策略及模型状态转移一致，同时量化安全开销后的效率收益？**

这条主线与点一的递进关系是：点一回答“同步轮次的聚合和是否正确”；点二回答“跨版本、跨检查点的合法组包是否按照既定规则形成下一模型”。

| 当前内容 | 重构后的定位 |
|---|---|
| 单 TA、LHH、边缘验证 | 继承点一的约束和基础设施 |
| 组包 buffer + checkpoint | 点二的系统组织方法，承认已有缓冲/组级异步先例 |
| Direct-VCM | 基版本对齐与可验证重构组件，说明与增量聚合等价 |
| 策略来源、基版本、令牌、结果绑定 | 值得重点论证的协议贡献候选，但要证明超出通常的签名字段检查 |
| TA ledger、receipt、提交一致性 | 支撑跨 checkpoint 状态安全；不把数据库工程本身列作密码学创新 |
| stale reuse、固定 σ、Aσ、多类调参模块 | 附录或边界分析，主线不继续堆叠 |

需要增加的实质论证，而非只换标题：

1. **统一可验证关系**：定义 `W_next = F(config, committed_history, Q, verified_sum)`。明确配置、基版本、参与元数据、权重和已消费状态如何绑定；说明每一步哪些量可由诚实边缘独立复算。
2. **组合性质**：给出正确性、相对已声明泄露量的隐私保持、规则执行完整性、至多一次纳入以及拒绝不推进的清晰命题。隐私与完整性使用不同的合谋/诚实性前提时，分别列明。理想信道和完全可信 TA 可以保留。
3. **机制必要性实验**：构造“聚合线性等式仍通过，但基版本、策略来源或补偿参数被改动”的攻击，比较去掉绑定与完整机制的接受情况，说明新增验证对象确实超出点一。选中集合之外的静默漏选与抗审查按既有边界明确出界。
4. **成本收益证据**：保持学习算法一致，比较同步安全聚合、组级增量异步明文版本、完整可验证半异步版本，量化异步收益和新增安全成本。再与忠实外部基线比较。

已有单 checkpoint 偏差上界可保留，但宜称“条件性偏差分析”。其当前假设是一步映射、相同选中集合/权重与耦合随机性，不等于真实多轮 Non-IID 收敛证明；较小上界也不保证每个样本轨迹实际误差下降。对专硕安全系统主线而言，可优先完成协议性质和实证边界，不必为了形式完整强行添加不成立的收敛定理。

## 7. 何时才值得进一步改算法

**先用 2–4 周修正基线和定位，再决定是否增加一个机制。**当前不建议继续围绕 `γ/σ/reuse` 寻找小幅涨点，因为增量基线不正确时，涨点的含义不清楚。

出现以下情况之一，才需要更深的方法重构：

- 正确增量基线和安全成本纳入后，在合理异构设置中找不到有用的效率—精度权衡；
- 与 Buffalo 等近邻比较后，协议性质、成本或应用约束没有可说清的差异；
- 新增验证仅检查不参与主方法的可选模块，核心训练流程本身没有新增验证对象。

若确实需要一个增量研究机制，优先考虑**公开漂移约束下的组包准入与 checkpoint 选择**：用公开的 `||W(t)-W(r_k)||`、陈旧度、样本量与已测安全成本定义可复算的准入/触发规则；分析等待、版本误差与验证频率的权衡。它比盲目加补偿模块更接近现有系统的约束，但目前只是候选方向，需要单独检索和试验，不能预先宣称创新或有效。

有限的适用场景也可以形成专硕贡献：关键是把适用条件、开销代价和失败边界说明白。无需要求一个方法在全部数据分布上都最高准确率。
