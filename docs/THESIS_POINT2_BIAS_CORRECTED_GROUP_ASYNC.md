# 研究点2定稿版：提前分组、偏置校正与检查点审计的双辅助服务器可验证半异步联邦学习

## 1. 推荐结论

研究点2最合适的方案不是直接照搬单篇异步论文，也不是把多个工作机械拼接，而是采用一个收缩后的 `A+` 方案：

`FedFleet 的提前分组 + Fed-RAA 风格资源感知训练预算 + 组内 HVSA 式安全同步聚合 + HGA-FL 风格云端偏置校正 + 自身的检查点审计`

对应的一句话定义可写为：

> 在研究点1的双辅助服务器可验证安全聚合框架基础上，本文引入时延感知提前分组与资源感知训练预算自适应，使组内用户基于同一全局模型进行定时同步安全聚合；云端对通过组级验证的组更新进行缓冲和偏置校正后再执行半异步全局更新，并通过检查点重放验证最终全局模型完整性。

推荐题目：

- 题目1：基于双辅助服务器可验证安全聚合的提前分组偏置校正半异步联邦学习方法
- 题目2：面向分层联邦学习的可审计偏置校正组间异步安全聚合机制
- 题目3：兼顾训练时延与模型完整性的分组半异步可验证联邦学习方案

优先推荐题目1，因为它同时体现了：

- 研究基础：双辅助服务器可验证安全聚合
- 研究策略：提前分组
- 异步特点：组间半异步
- 方法亮点：偏置校正

## 2. 为什么选这个方案

### 2.1 为什么以 FedFleet 为结构骨架

FedFleet 的核心贡献并不是安全机制，而是把设备异构下的训练组织方式拆成了两层：

- 组内同步
- 组间异步

这与当前研究点1的密码流程天然兼容。原因在于：

- 组内用户从同一全局模型出发，便于绑定同一轮次和同一参与集合。
- 安全聚合、部分解掩码和验证都可以继续围绕一个固定的组级在线集合开展。
- 相比客户端级完全异步，这种结构对现有代码改动更小，也更容易解释清楚。

因此，FedFleet 适合借来做研究点2的训练组织骨架，而不是借它的全部系统实现。

### 2.2 为什么借 HGA-FL 的偏置校正而不是照搬全部方法

HGA-FL 的真正可借之处，不是其本地正则化细节，而是全局层的两个思想：

- 用 `buffer` 吸收异步到达的子中心更新
- 用状态变量和偏置校正项减轻陈旧更新带来的方向偏差

对当前研究点2而言，最有价值的是第二点。因为提前分组主要解决的是“等”的问题，即减少组内和组间等待；而偏置校正解决的是“偏”的问题，即慢组或旧组更新参与全局融合时引入的方向偏移。

这里不建议把 HGA-FL 的 local regularization alignment 一起拉进来，原因是：

- 当前仓库聚合的是模型参数向量，不是论文理论里更典型的梯度接口。
- 研究点2的主角应保持为“安全聚合框架的异步扩展”，而不是“重做一个本地优化算法”。
- 只借云端偏置校正思想，能最大限度保持用户侧、边缘侧和双辅助服务器接口不变。

### 2.3 为什么不把 MAFSA 作为主线

MAFSA 的 stale reuse 和 boosting factor 更适合作为对照思路，而不适合作为研究点2主线。原因在于：

- 它依赖客户端级旧更新复用，而当前安全聚合方案的掩码、组级验证和在线集合绑定的是当前轮次的 `S_g^r`。
- 一旦复用历史客户端更新，就需要重新定义掩码会计、历史更新的可验证性和旧模型的合法来源。
- 这会明显扩大协议改造范围，容易把研究点2从“分层半异步扩展”变成“新安全协议重构”。

因此，MAFSA 可以在相关工作中讨论，也可以在后续工作中作为组级 stale reuse 的启发来源，但不建议纳入本研究点2的主协议。

### 2.4 为什么只借 Fed-RAA 的能力画像与训练预算自适应

Fed-RAA 的核心贡献是“子模型自适应分配 + 异步聚合 + 在线贪心分配 + 理论收敛保证”。但对当前研究点2而言，真正适合借用的并不是整套机制，而是其中最轻量、最兼容的一部分：

- 资源能力画像：根据客户端算力 `p_n` 与带宽 `b_n` 估计其资源水平
- 有界训练预算自适应：让资源更强的设备承担略多的本地训练量

其中，最值得借鉴的是“按资源画像调整训练量”的思想，而不是它的子模型异步框架。原因有三点：

- 当前双辅助服务器安全聚合协议默认所有参与者上传的是同维度全模型参数向量，子模型切分会破坏掩码维度、组级验证对象和检查点重放对象的一致性。
- Fed-RAA 的客户端级立即重分配依赖参数服务器在任意时刻给空闲客户端分配新的子模型，这与当前研究点2“组级验证后再异步更新”的组织方式不同。
- Fed-RAA 的理论保证绑定在“子模型异步分配 + staleness 加权 + 特定局部正则项 + 延迟上界 `K` + 更新不平衡比 `δ`”这一整套设置上，因此不能直接拿来为当前方案的“训练预算自适应”背书。

因此，研究点2对 Fed-RAA 的最佳吸收方式应当是：

- 借资源能力画像
- 借有界训练预算自适应
- 不借子模型切分
- 不借客户端级立即重分配
- 不直接继承其理论收敛结论

这也是最符合当前安全假设、实现成本和论文边界的做法。

## 3. 系统模型与基本原则

本研究继承研究点1的基本安全模型：

- 用户上传的是掩码后的模型参数向量，而不是单步梯度。
- 双辅助服务器 `A1`、`A2` 独立持有不同种子材料，分别计算部分掩码。
- 边缘服务器负责组级预聚合与验证证据生成。
- 云服务器可能是恶意的，可能篡改、伪造、重排或漏掉更新。
- 验证逻辑保持 `edge-centric`，最终通过检查点审计约束云端行为。
- 组级聚合对象始终是同维度全模型参数，不采用子模型切分。

研究点2必须满足五条设计原则：

1. 用户侧仍保持“一次本地训练 + 一次掩码参数上传”，不引入复杂额外交互。
2. 异步的最小更新单元是组级聚合结果，而不是单个用户。
3. 云端只有在组级验证通过后，才能把该组结果纳入异步全局更新。
4. 所有偏置校正状态都必须纳入审计日志，不能成为云端的不可见内部变量。
5. 资源感知训练预算只能做有界自适应，不能导致组内训练量失衡无限扩大。

## 4. 推荐协议流程

### 4.1 初始化阶段：时延感知提前分组

设系统共有 `N` 个用户、`G` 个边缘组，每个组对应一个边缘服务器 `e_g`。训练开始前，对用户进行一次提前分组。

若实验中可以测得本地训练时间和通信时间，则定义用户时延画像为：

`d_i = t_i^train + t_i^comm`

若当前只能稳定测得通信时延，则退化为：

`d_i = t_i^comm`

随后按 `d_i` 排序，并划分为 `G` 个组：

`U_1, U_2, ..., U_G`

这样做的目的不是改变安全协议，而是让同组用户的完成时间更接近，从而降低组内同步等待。

### 4.1.1 资源感知训练预算自适应

在提前分组完成后，可进一步借鉴 Fed-RAA 的资源感知思想，对各组设置有界训练预算，而不是让所有组使用完全相同的本地训练轮数。

可先根据客户端算力 `p_i` 和带宽 `b_i` 构造能力画像，例如：

`r_i = omega_p * norm(p_i) + omega_b * norm(b_i)`

再将用户或组划分为 `Level 1 / Level 2 / Level 3` 三个能力等级。为了最大限度保持组内同步结构，建议第一阶段采用“组级统一预算”而不是“用户级不同预算”，即：

- 强组：`E_g = E_max`
- 中组：`E_g = E_mid`
- 弱组：`E_g = E_min`

其中应显式约束训练预算不平衡比：

`delta_E = E_max / E_min <= C`

这里的 `C` 应为一个小常数，用于避免训练量差异过大引发明显的组间方向偏移。这样做的目的不是复制 Fed-RAA 的子模型自适应训练，而是在保持全模型同维度、同协议接口的前提下，让强组略多训练、弱组略少训练，从而进一步缓解设备异构导致的本地训练拖尾。

需要特别说明的是，这里只是借用了 Fed-RAA 的资源感知思想，而不是直接继承其理论结论。因为本文不采用子模型异步分配与客户端级立即重分配机制。

### 4.2 组内训练与组级安全聚合

在第 `r` 轮开始时，云端广播当前全局模型 `W^r`。组 `g` 内所有用户均基于同一个 `W^r` 本地训练，并使用该组预先分配的本地训练预算 `E_g`。

用户 `u_i` 完成训练后得到本地模型参数 `w_i^{g,r}`，并上传掩码参数：

`wbar_i^{g,r} = w_i^{g,r} + m_i^(1)(g,r) + m_i^(2)(g,r)`

其中：

- `m_i^(1)(g,r)` 来自辅助服务器 `A1`
- `m_i^(2)(g,r)` 来自辅助服务器 `A2`

边缘服务器 `e_g` 在截止时间 `tau_g^r` 到达后封组，得到本轮实际在线集合：

`S_g^r subseteq U_g`

并计算组级掩码和：

`Wbar_g^r = sum_{i in S_g^r} wbar_i^{g,r}`

### 4.3 组级解掩码与组级验证

边缘服务器将 `(g, r, S_g^r)` 发送给两个辅助服务器。随后：

`M_{g,1}^r = sum_{i in S_g^r} m_i^(1)(g,r)`

`M_{g,2}^r = sum_{i in S_g^r} m_i^(2)(g,r)`

云端恢复该组明文和与平均模型：

`W_g^r = Wbar_g^r - M_{g,1}^r - M_{g,2}^r`

`Wtilde_g^r = W_g^r / |S_g^r|`

组级验证继续保持研究点1的边缘验证风格：

`H_plain(g,r) + H_mask^(1)(g,r) + H_mask^(2)(g,r) = H_masked(g,r)`

其中：

- `H_masked(g,r) = LHH(Wbar_g^r)`
- `H_plain(g,r) = LHH(W_g^r)`

建议边缘服务器签名时同时绑定以下对象：

`(g, r, hash(W_base^r), digest(S_g^r), |S_g^r|, H_masked(g,r))`

这里的 `hash(W_base^r)` 非常重要，因为后续偏置校正和检查点重放都必须知道该组更新是基于哪个全局基模型产生的。

### 4.4 云端 verified buffer 与偏置校正

这是本研究点2相对于原始分组异步方案的关键增强。

对每个通过验证的组结果，不直接立即写入全局模型，而是先构造组级模型差分：

`Delta_g^r = Wtilde_g^r - W^r`

然后把 `(g, r, Delta_g^r, hash(W^r), s_g^r)` 送入云端的已验证缓冲区 `H_t`。

其中，组级陈旧度定义为：

`s_g^r = v_cur - r`

当缓冲区达到容量 `B` 时，云端执行一次带偏置校正的异步更新。借鉴 HGA-FL 的状态校正思想，可定义每个组的状态变量 `c_g` 为“最近一次被全局接纳的组级差分”。令：

`c_bar^t = (1 / G) sum_{g=1}^{G} c_g^t`

对于当前缓冲区中的组集合 `H_t`，定义偏置校正项：

`v_t = (1 / |H_t|) sum_{g in H_t} (c_bar^t - Delta_g^r)`

然后执行全局更新：

`W^{t+1} = W^t + eta_t * ((1 / |H_t|) sum_{g in H_t} Delta_g^r + v_t)`

其中，学习率可继续保留陈旧度衰减思想，例如：

`eta_t = lambda_0 / (1 + s_bar_t)`

`s_bar_t = (1 / |H_t|) sum_{g in H_t} s_g^r`

这样，提前分组负责减少等待时间，资源感知训练预算负责缓解组内训练拖尾，偏置校正负责减轻陈旧更新带来的方向偏移，三者是正交互补的。

### 4.5 检查点审计与最终模型完整性验证

研究点2不要求每次异步提交都公开做重型在线证明，但必须保证最后的全局模型可以被审计重放。

为此，云端每次执行一次 buffer 提交时，都写入一条审计日志：

`(buffer_id, groups, base_model_hashes, delta_hashes, staleness_stats, hash(c_before), hash(v_t), hash(c_after), hash(W_before), hash(W_after))`

到达检查点时，验证方从上一个可信检查点模型 `W_ckpt` 出发，按照日志顺序重放所有已接受的 buffer 更新，独立重建得到 `W_ckpt'`。若：

`hash(W_ckpt') = hash(W_cloud_final)`

则接受最终全局模型，否则判定云端发生了以下一种或多种行为：

- 篡改最终全局模型
- 篡改偏置校正项 `v_t`
- 篡改状态变量 `c_g`
- 重排 buffer 提交顺序
- 漏掉某个已验证组
- 为某个组错误绑定旧基模型

## 5. 该方案的真正创新点

研究点2的创新点不应表述成“我也做了异步”，而应表述成下面三点。

### 创新点1：时延感知提前分组与有界训练预算自适应下的组级安全聚合扩展

将研究点1中的整轮同步安全聚合扩展为“提前分组 + 有界训练预算自适应 + 组内定时同步 + 组间半异步”的分层结构。在不改变用户侧单次掩码参数上传接口的前提下，同时缓解异构环境下的组内等待与本地训练拖尾问题。

### 创新点2：面向已验证组级更新的偏置校正异步融合

在组级验证通过后，不直接采用普通异步平均，而是引入面向组级差分的偏置校正机制，通过云端缓冲与状态变量修正陈旧组更新带来的方向偏移，提高异构与重尾延迟场景下的收敛稳定性。

### 创新点3：适用于偏置校正半异步更新的检查点审计机制

将组级证据、基模型绑定、校正状态和异步日志统一纳入可重放审计框架，实现对最终全局模型完整性的验证，使云端即使持有异步调度权，也无法在不留下痕迹的情况下篡改全局模型。

## 6. 与备选拼法的关系

### 6.1 与“只做 FedFleet 分组异步”的区别

只做 FedFleet 风格分组异步，只能说明“减少等待”。本方案额外引入偏置校正和检查点审计，能够同时回答：

- 为什么异步后模型方向不会明显漂移
- 为什么恶意云端不能随意改异步融合结果

### 6.2 与“MAFSA stale reuse”的区别

MAFSA 更关注客户端掉线后的旧更新复用与公平性，而本方案关注：

- 双辅助服务器安全聚合流程的兼容性
- 组级验证的连续成立
- 云端异步更新的可审计性

因此，两者的问题意识不同，研究点2不应直接以 MAFSA 作为主干。

### 6.3 与“完整 HGA-FL”方案的区别

本方案并不试图复现 HGA-FL 的全部局部优化细节，而是只借用其全局层的偏置校正思想。这样做有两个好处：

- 保住了当前仓库“模型参数上传 + 参数平均”的实现口径
- 让研究点2的主角仍然是自己的双辅助服务器可验证安全聚合框架

### 6.4 与“完整 Fed-RAA”方案的区别

Fed-RAA 的完整方案包含：

- 子模型切分
- 客户端级异步立即聚合
- 在线贪心子模型分配
- 面向子模型异步训练的收敛分析

而本方案仅吸收其中与当前安全协议兼容的部分：

- 资源能力画像
- 有界训练预算自适应

不吸收的部分包括：

- 子模型切分与不同维度上传
- 客户端级立即重分配
- 直接沿用其理论收敛结论

原因在于，当前研究点2必须保持：

- 同维度全模型聚合
- 双辅助服务器部分解掩码闭环
- 组级验证对象稳定
- 检查点审计可重放

因此，本方案与 Fed-RAA 的关系应表述为“受其资源感知思想启发”，而不是“安全版 Fed-RAA”。

## 7. 实验设计建议

### 7.1 对比方法

建议至少做四组主实验：

1. `Sync-HVSA`：研究点1的整轮同步方案
2. `Grouped-HVSA + Inter-Group Sync`：只做提前分组，但组间仍同步
3. `Grouped-HVSA + Inter-Group Async`：提前分组 + 组间异步，但不做偏置校正
4. `Grouped-HVSA + Inter-Group Async + Bias Correction`：本文完整方案

若篇幅允许，可再加一个安全攻击实验组，而不把攻击组作为普通基线方法。

### 7.2 异构环境设置

建议沿用 FedFleet 的实验表达方式，并结合 Fed-RAA 的资源画像设定：

- 用 `H` 或 `DH` 指标量化设备异构程度
- 用 `d_i = t_i^train + t_i^comm` 或 `d_i = t_i^comm` 构造分组依据
- 用 Pareto 重尾延迟模拟极端异构与突发拖尾
- 用 `Level 1 / 2 / 3` 能力分级刻画不同算力和带宽组合，例如 `30% 强 / 30% 中 / 40% 弱`
- 为不同组设置有界本地训练预算 `E_g`

### 7.3 指标

建议汇报以下指标：

- 达到目标精度所需墙钟时间
- 平均组内等待时间
- 最终测试精度
- 平均组级陈旧度
- verification overhead
- tampering detection rate

### 7.4 消融实验

建议至少做四组消融：

1. 是否提前分组
2. 是否启用资源感知训练预算自适应
3. 是否进行偏置校正
4. 是否开启检查点审计

这样可以分别验证“分组解决等”、“训练预算自适应缓解拖尾”、“偏置校正解决偏”、“审计解决可信性”。

### 7.5 攻击实验

攻击实验可聚焦三类即可：

- 篡改最终全局模型
- 篡改偏置校正项或状态变量
- 重排或遗漏 buffer 提交日志

这三类足以支撑“最终全局模型完整性验证”的主张。

## 8. 对现有仓库的实现映射

若按当前代码结构推进，实现改动可集中在以下几个文件：

- `main.py`：增加时延采样、用户提前分组、能力画像、组级训练预算与 buffer 驱动的全局更新
- `edge.py`：从整轮聚合改为组级封组、组级签名、组级证据生成
- `ta.py`：从整轮在线集合改为按 `(g, r, S_g^r)` 计算组级部分掩码
- `cloud.py`：增加 verified buffer、状态变量 `c_g`、偏置校正项 `v_t`、异步日志与检查点重放

建议实现顺序如下：

1. 先完成“提前分组 + 组内定时同步 + 组间异步”的基础版
2. 再加入资源感知训练预算
3. 再加入 verified buffer
4. 再加入偏置校正 `v_t`
5. 最后补检查点审计

这样每一步都能独立做实验，也更容易排查正确性。

## 9. 可直接放论文中的总结表述

研究点2最稳的表述不是“本文设计了一个全异步安全联邦学习算法”，而应写成：

> 本文在双辅助服务器可验证安全聚合框架基础上，提出一种面向分层联邦学习的提前分组偏置校正半异步聚合方法。该方法首先依据用户训练与通信时延画像进行提前分组，并引入资源感知的有界训练预算自适应机制，使同组用户在同一全局基模型上执行定时同步安全聚合；随后，云端对通过组级验证的组更新进行缓冲和偏置校正后再执行半异步全局融合；最后，通过检查点重放实现对最终全局模型完整性的审计验证。该方法在不破坏现有安全聚合与验证闭环的前提下，同时缓解了设备异构导致的等待开销、本地训练拖尾和异步更新带来的陈旧偏差。
