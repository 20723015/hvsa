## 结论先行

1. **“组级半异步/动态分组/异构适配”单独不足以成为点二的区别点。**严怡婷已有动态集群半异步 FL；王之路、蒋思宇、余思溢等分别已有分组、层级、设备/资源异构的优化方法。点二若只讲减少等待、分组、按版本把旧模型增量平移到当前模型，评审很容易判为既有调度与常规模型差分的组合。
2. **基础版本对齐不宜单独宣称创新。**在 `γa=1`、不衰减、权重归一的默认情形，`W_t + Σ p_k(U_k − V_k)` 是以公共基点表达的标准增量聚合恒等式。它能作为协议正确性的必要构造，但本身没有产生新的补偿规律，也没有给出新的收敛或偏差性质。见中期讲稿 v4 P8及《THESIS_FULL_DESIGN.md》。
3. **相对这组材料，最能独立支撑研究点二的方向是“半异步检查点中，对冻结后的选中组包、基版本和聚合/补偿规则执行进行绑定与可核验”。**这不要求证明 Cloud 看到了所有候选包或公平选择了集合 Q：协议可在 Q 冻结后绑定 token 与包身份，保证后续不能替换/重放已选包，并核验 Q 上公开策略的执行。全候选池完整性、静默漏选、抗审查或公平选集属于更强的调度证明，当前主线不覆盖。本次样本未见这一精确定义的组合，不能据此声称全领域首次。
4. **矩校准/组级适配仍是候选设计，尚不能作为当前已完成的贡献。**要成立，需给出非平凡且确实改变默认增量平均行为的规则，明确其偏差补偿目标、定义和公开信息边界，并证明该规则能从各组异步数据推导出来；还需使 ES 能对策略、系数输入和历史状态独立复算。现有签名/LHH 对线性聚合结果的完整性验证，不会自动证明隐藏客户端更新的范数统计、EMA 或非线性校准输入正确。
5. **风险最大的是贡献边界过宽。**HVSA 点一已验证聚合和最终模型重构；点二若仍沿用同一掩码、LHH、签名和 TA 机制，单纯把同步参与集合换成组包/checkpoint，会被看成既有安全聚合的运行模式扩展。应把新增对象限定为异步下冻结 Q 的包/基版本/权重及相关状态，给出针对它们的协议不变量、拒绝条件及可复核分析，而不是把已有模型重构或“安全聚合”本身再次记作点二新贡献。

### 五篇北京交通大学专业学位论文的设计粒度参照

这五篇只用来观察设计贡献怎样落到一个具体问题和方案，不把它们的题目里“有几个技术名词”当作创新数量，也不据此推断当前论文必然通过答辩。它们呈现出不同的、可讲清楚的贡献结构：

- **张君豪**将无人机云边端数据共享拆成端边身份认证/密钥协商与端端安全数据共享两项问题；各自有协议对象、参与实体、威胁模型和验证过程（PDF 3–5，正文第3、4章目录见PDF 9）。可比点是问题分解和系统角色清晰，不是链上组件数量。
- **杨柳**围绕智能合约威胁防护组织为已知漏洞检测、未知威胁迁移检测、跨链攻击防护三层；后两层由前面的检测能力延展，论文总结按三类威胁分别说明作用（PDF 3–5、85）。这说明多项设计可由一个安全问题串成递进主线，但跨链防护也明确依赖既有漏洞检测扩展。
- **解宇航**的跨链服务、SDN-IoT 数据共享、可信路由分别解决服务匹配/数据机密性/路由攻击问题，使用不同系统模型与攻击目标（PDF 3–5，章节目录PDF 6–7）。这更像同一 IoT 安全共享主题下多个独立子问题，不能因“有三项”就直接折算为比两项工作多。
- **王岚锐**把车辆身份认证与跨域数据共享分为两个方向；前者用假名/隐式证书及快速重连处理移动环境，后者关注可搜索加密、数据完整性与二次共享（PDF 3、63–64）。贡献粒度由新的场景约束和相应协议流程决定。
- **吕蒙**组合了多模态异常检测、轻量迁移学习适配器和运维监测平台三种不同交付，但三者共同服务于微服务运维中的检测准确性、迁移成本和数据管理问题（PDF 3–5、59）。适用于说明工程系统贡献也可形成论文设计，但它与 FL 聚合安全并非技术近邻。

就当前 HVSA 点二而言，专业学位层面的设计定位不必复制以上任何一篇的主题或子项数。更关键的是把主问题收敛为：**既有分层可验证安全聚合遇到异步跨版本组包后，如何在 Q 冻结后绑定所选包并定义唯一可核验的聚合语义，使不可信 Cloud 不能在冻结后替换包、基版本或规则而仍通过边缘核验。**这不声称 Q 在冻结前是完整、唯一或公平的候选选择。矩校准可以成为该主问题中的算法支线，但不应为了凑贡献点而与协议支线并列成互不相关的题目。

## 对当前点二的判断

当前 v4 主线把研究点二表述为：**组级半异步 + 基础版本对齐 + 待完成的矩校准组级适配 + 待完成的统计/历史核验**；2026-10-09 份额驱动调度仅是备选，不能写成既有成果。评估中应把“做出来了什么”与“有机会形成什么贡献”分开：

- **已实现原型的组级半异步**：提供新运行环境和必要系统机制，但调度本身已被严怡婷的 FedDcp、以及多篇分组/资源异构工作覆盖。需要准确说出新增难题是恶意 Cloud 在 Q 冻结后替换、重放组包，或错用基版本/权重/历史状态；不能声称当前方案证明 Cloud 选择了完整、公平或唯一的候选集合。
- **已实现的基础版本对齐**：只说明以共同基点表达组更新并在新模型上重构。默认系数与归一化下等价增量聚合，应定位为正确性基线/协议适配步骤，不能独立支撑“版本补偿算法”或声称已补偿统计偏差。
- **候选矩校准**：如果推导能表明不同组版本/漂移在统计意义上造成特定偏差，并给出基于历史矩的可识别补偿量，且在共享基版本、统一统计窗口/分母、无未声明裁剪等条件下严格成立，就有机会成为算法贡献。若系数只是已有 VCM/DVAFL 公式代入组权重、或默认落回 γ=1，则属于已有算法在分层 FL 的组合/适配，贡献强度较弱。需把统计对象、客户端级校正、组聚合等式、失效条件和稳定性界写明。模块尚在适配阶段不等于设计不成立；只有当组级推导没有闭合、统计输入无法按声明取得，或与普通增量聚合完全等价却仍声称非平凡补偿时，才是设计层面的缺口。
- **可验证执行**：可以构成独立的协议/系统贡献，前提是核验“冻结集合 Q 上的策略是否按公共声明执行”，而非只验“给定结果是否等于给定线性和”。每一 checkpoint 至少要把冻结后的 token/组包身份与至多一次纳入、基版本、Q 内参与客户端集合摘要、样本量、补偿策略版本及参数、所依赖历史状态摘要、结果摘要和 TA 授权绑定；ES/TA 应从可信状态独立重算关键规则并拒绝改标、换包、换权重、重放、错误历史或伪造 receipt。矩统计若由客户端从真实更新计算，应认证其输入与 token 关联、按版本维护历史递推，并由 ES 独立复算 Cloud 对冻结 Q 的策略执行结果。这个结论不包含候选池完整性、静默漏选、抗审查、公平选集或“Q 是唯一合法选择”的证明。LHH 不自动证明非线性统计本身，但这不意味着必须引入零知识证明；应依据统计值来源和协议假设决定证明边界。

## 最强反对意见

1. “FedDcp 已做动态集群半异步，其他论文已做分组和层级异构 FL；你只是把它接到 HVSA 上。”
2. “`W_t + Σ p_kΔ_k` 是平均增量的改写，γ=1 的默认策略与普通聚合相同，没有新优化目标或算法性质。”
3. “VCM 矩校准公式是现成的个体/客户端级补偿搬到组级；如果组系数在共享基点和公用分母下只是加权均值代数变形，组级本身没有新理论。”
4. “LHH 对线性和的核验不证明策略正确：若 Q 冻结或输入认证没闭合，Cloud 可以在冻结前审查候选包，或在冻结后替换已选包、改变权重/历史版本/非线性统计输入；TA/ES 只验证结果摘要是协议拼装，不是实际客户端更新的可验证计算。”
5. “隐私、安全和异步由不同假设分别保证，合在一套架构不等于联合安全结论。尤其 TA 可信不合谋、理想安全信道、诚实 ES 的边界必须明确；不可把验证宣传为抵抗恶意边缘。”

## 最少必须补齐的设计

1. **贡献定义与对照表**：把严怡婷 FedDcp、王之路 EPFL/GSFL、蒋思宇 HCFL-CM/ANHFL-KD、田宇/张翱男安全聚合分别对照。用“本文新增的协议对象/威胁/定理”描述区别，避免列技术名词。明确 Q 在何处冻结，以及 Cloud 在冻结前可有何种选择权；验证结论只覆盖冻结后 Q 内执行。
2. **明确非平凡适配规则**：先重现原始 DVAFL/VCM 更新式并标注来源；推导组级等式及所有成立条件；指出何时不等价于普通增量平均、校准到底修正哪种偏差。若不存在稳定、可识别的增益，缩小或撤下“矩校准算法创新”，保留基础对齐作为系统基线。
3. **检查点状态机和串谋模型**：定义 package/token 的签发、缓存、封组、超时/水位触发、Q 冻结、TA prepare/finalize、Cloud 提交、ES 推进和崩溃恢复；逐个列出冻结后替换、重放、重复纳入、换基版本、换权重/γ、换历史统计的攻击及拒绝条件。把冻结前的候选遗漏、Cloud 审查或选集公平性明确排除在保证之外。继续遵守既定隐私边界 `N_Q-c≥2`；不要求至少两个组，但至少满足客户端级阈值。
4. **补策略可核验闭环**：公共策略配置版本化并绑定摘要；矩统计与真实更新、客户端和 token 的来源关联经过认证；按版本维护历史状态；权重与补偿参数由 ES/TA 从声明输入和历史共识状态独立重算；receipt 绑定同一 raw sum、聚合掩码/其摘要、最终模型及 token 集合，提交/推进做幂等与冲突检查。将密码学结果完整性和输入统计来源假设分开陈述，不把 LHH 线性核验说成能直接证明非线性统计。
5. **给出适配后的正确性/安全论证**：将聚合值完整性、策略一致性、至多一次纳入、隐私和条件性模型偏差分别陈述，不用一个 LHH 等式概括全部。核心安全结论需明确可信 TA 永不合谋、Cloud 可与全部 ES 及最多 `N−2` 客户端合谋、ES 诚实执行核验且通信为理想安全信道；若改变假设，需要同步改协议与证明。
