# 研究点二候选：历史增量差分校准与可验证联合提交

日期：2026-10-08。状态：明文原型及六配对开发筛选已完成；当前适配未确认稳定涨点，暂缓晋级，尚未接入安全协议。

**本方案最初被推荐优先试验“历史增量差分校准”，借鉴 CA²FL/FedVARP 的缓存校准思想及 2026 年 FedGS 的客户端差分上传思路。VCM 保留为基版本对齐组件。算法思想明确归属于既有研究；拟研究的增量在于掩码差分聚合、跨版本缓存状态及模型—缓存联合提交的组合。六配对明文筛选未显示稳定收益，详见第 12 节；独立新颖性也尚未成立。**

## 1. 为什么选它

默认 Direct-VCM 为 `W_next = W_t + 平均本地增量`，不能额外解决部分参与的更新方差，也没有消除增量的方向陈旧。当前半异步每个 checkpoint 只采纳部分组，存在缓存校准的作用空间。

与继续调 gamma/sigma 相比，缓存校准改变聚合方向所包含的信息，而非仅改变旧基点的混合比例。与 SCAFFOLD 本地梯度校正相比，以下设计保留原本的本地训练器，不要求按普通 SGD 的步数公式估计控制变量。本仓库 `models.py:131` 使用本地 momentum=0.9；`datasets.py` 的 Non-IID 划分产生不同样本数，因此不能直接套用“统一 E×eta”的 SCAFFOLD 重构公式。

仓库已有的 FedProx 小收益/零收益、限幅与曲率外推失败，只约束已试验的适配和场景；不能据此断言整个客户端漂移校正或方向修正领域无效。Aσ 的 CIFAR 收益已有确定性复核否定，见 `ASIG_VCM_REVIEW.md`，不宜继续充当新增模块的效果依据。

## 3. 最小数学设计

先固定客户端名册和本地样本权重 `n_i`。设总样本权重 `N_all = Σ_i n_i`，本次已采纳用户集合为 `I_t`，`S_t = Σ_(i∈I_t) n_i`。本地训练器保持不变：

\[
\Delta_i^t = w_i^t-W_{r_i}.
\]

客户端保存其**最近一次已提交**的本地增量 `h_i`，初值为零。全局参考状态为

\[
H_t=\frac{1}{N_{\rm all}}\sum_i n_i h_i.
\]

本次客户端构造并掩码上传差分 `d_i = Δ_i^t-h_i`。组内及跨组继续执行加性安全聚合，只恢复

\[
D_t=\sum_{i\in I_t}n_i d_i.
\]

模型及参考状态的候选转移为

\[
W_{t+1}=W_t+H_t+\frac{D_t}{S_t},\qquad
H_{t+1}=H_t+\frac{D_t}{N_{\rm all}}.
\]

模型使用**更新前的** `H_t`。提交成功后，入选用户更新 `h_i←Δ_i^t`，其他用户保留原值。这里模型分母是入选样本权重 `S_t`，缓存分母是总体权重 `N_all`，不可混用。

它与标准增量聚合的差异是

\[
H_t+\frac{D_t}{S_t}
=\frac{\sum_{i\in I_t}n_i\Delta_i^t}{S_t}
 +\left(H_t-\frac{\sum_{i\in I_t}n_i h_i}{S_t}\right).
\]

括号内是总体历史参考与本次参与子集历史参考的差异，一般不为零。因此这次确实增加了标准增量聚合没有的校准项。

两个必要边界：冷启动时所有缓存为零，首个 checkpoint 与增量聚合相同；全员参与时，校准项严格抵消，与标准增量聚合相同。在均匀抽样等相应条件下才可讨论估计性质；当前固定速度的组级异步、样本加权比值聚合不能直接声称无偏，更不能声称消除了全部陈旧性。

### 保留现有 VCM 管线的适配

可将上传向量定义为 `z_i = W_(r_i)+d_i`，保留按样本量掩码聚合完整向量的接口。现有 gamma=1 对齐会得到 `W_t+D_t/S_t`，再加 `H_t` 得到上述模型转移。`z_i` 是协议构造向量，**不是实际本地训练终点模型**；元数据、日志和量化分析必须使用正确语义。另一实现是直接上传 `d_i`，相应改写重构接口，不能再次叠加完整模型的 VCM 补偿。

## 4. 为什么不同于此前失败的 stale reuse

旧 reuse 混合旧完整模型或旧增量，目标常是填补缺席贡献。本候选通过“当前更新减该用户历史参考，再加总体历史参考”校准部分参与带来的方向变化，并同步维护参考均值。旧缓存不是重新提交的组包，不能再次消费旧 token。

这一区别提供不同的试验假设，**不保证新模块不会遭遇陈旧缓存伤害**。长期掉线、从未参与的客户端、速度与标签强相关时，历史参考可能失效；这些场景应单独报告。不能引用 CA²FL/FedGS 的结果代替本仓库实测。

## 5. 真正需要新增的验证对象

在现有可信 TA、诚实客户端训练等前提下，拟维护不变量

\[
H_t=\sum_i(n_i/N_{\rm all})h_i^{\rm committed}.
\]

**模型、全局缓存、客户端缓存必须由同一提交事件推进。** 建议接入已有 `package_token`、receipt 和提交事务：

1. 客户端训练后暂存新缓存；ES 接收上传不等于全局采纳，不立即覆盖已提交缓存。
2. 组包携带并绑定训练基版本、已提交缓存序号、用户集合和固定权重；同一用户只允许一个未决缓存更新。
3. ES 依据已验证的 `D_t`、本地已提交 `H_t/W_t`、认证集合和权重，独立重算两个新状态。LHH 检查差分聚合和，状态转移检查重构规则。
4. TA receipt 绑定 `W_next`、`H_next`、入选 token 与先前状态摘要；成功提交才推进对应客户端缓存。
5. 验证失败保持旧状态并按原 token 重试；确定过期/终止后丢弃暂存缓存。通知丢失时先查询提交状态，不可擅自回滚已经提交的缓存。

可见的缓存均值是已公开状态及已释放聚合差分的确定性函数，故不需要另行公开单用户缓存。但仍需相对于声明输出分析多轮泄露，不能把“客户端上传差分”当作加密。单 TA 原有强信任边界保持。LHH 也不能证明客户端正确训练或诚实计算 `Δ_i-h_i`；恶意客户端问题不由本设计解决。

针对恶意云端的必要性攻击：保持线性聚合验证可通过，单独替换 `H_t`；只推进模型而跳过缓存；重试时重复推进缓存；把缓存增量的总体分母改成入选分母。比较仅结果验证与联合状态验证的接受差异，同时检查诚实、重试和恢复路径的误拒率。

## 6. 开销与实现边界

差分可替换原来的一个上传向量，不要求增加第二个模型大小的客户端上传。每个客户端多保存一个模型大小的已提交缓存及暂存状态；云端和验证边缘多保存全局缓存及必要历史/提交信息。校准和复算为 O(d)。签名、摘要、提交回执及向边缘同步状态仍有开销，不能称零通信或零存储成本。

本地 momentum=0.9 可以保留，因为缓存定义为实际模型增量，未使用普通 SGD 的平均梯度恒等式。不同本地步数依然影响增量尺度；先保持现有步数配置，随后以统一工作量对照检查是否需要额外归一化，不预先叠加 FedNova、动量或衰减。

量化必须统一：缓存保存与上传语义一致的编码增量，或给出两侧误差界；否则“未量化缓存＋量化聚合”会使不变量逐轮漂移。不能仅比较最终准确率来确认状态一致。

安全版本的一种明确编码规约是按固定 scale 先构造整数增量 `c_i_new = round(scale×Δ_i)`，客户端保存最近已提交的 `c_i_old`，上传整数差 `c_i_new-c_i_old`，而非对浮点差分重新单独量化。维护整数全局总量 `B_t=Σ_i n_i c_i_old`，提交时执行 `B_next=B_t+D_encoded`，并将模型方向重构为 `(B_t/N_all+D_encoded/S_t)/scale`。这样缓存不变量可在整数域精确记账；仍须检查模域溢出、带符号解码及模型浮点转换的误差。这是待实现的规约，当前 float64 筛选没有验证它。

当前 `u.p2_confirm_consumed()` 在 ES 接收后即可清理 stale 缓存；新校准缓存不能复用这个时点。需新增“接收/暂存”和“全局提交确认”的明确区分，具体回调可进入 `commit_tx.py` 及 receipt 通知路径。修改入口预计涉及 `user.py`、`cloud.py`、`edge.py`、`point2_types.py`、`commit_tx.py`、`main_point2.py`。

两臂使用一致数据划分、到达/掉线轨迹和配对的本地 minibatch 随机性。CIFAR 使用确定性模式。使用训练内验证集决定参数和规则，不从测试集或新种子结果反向挑选配置。

保留原 20-checkpoint 曲线检验短视界，同时延长运行检查历史参考是否需要暖机。主要报告共同预算内的等端到端时间精度、等实际本地 SGD/样本访问量精度、达到预定目标精度的时间与成功率。执行后过期的训练同样计入计算成本。

建议预先设定实用晋级线，例如目标任务配对均值至少 +0.5pp，或达到同一目标精度的端到端时间降低至少 10%；这些数值只是研究决策标准，不是预期收益或文献保证。开发阶段先看 2/3 种子的同向趋势，留出阶段再报告配对区间和最差种子，不因均值偶然为正就宣布晋级。

若原场景与留出验证均无稳定收益，或完整安全开销吞掉收益，关闭该候选。不要同时添加 gamma、sigma、EMA、多种权重来掩盖单模块结果。若只在明显参与偏斜的场景有效，按该适用范围表述。

## 8. 可用的贡献表述

## 10. 明文试验落地与单 checkpoint 误差关系

2026-10-08 后续已新增 `cache_calibration.py`（明文状态机）、`plain_cache_bench.py`（同事件循环配对）、`run_cache_screen.py`（六配对串行开发筛选）和 `analyze_cache_screen.py`（完整结果统计）。这是阶段一原型，尚未接入 TA 回执、边缘密码学验证及持久化恢复。实现允许暂存候选、拒绝不推进、确定终止后丢弃及幂等提交；没有要求客户端通知同步阻塞全局推进。正式网络协议仍须实现通知丢失后的状态查询。

新增 `tests/test_cache_calibration.py`，本次执行 6 个状态机测试全部通过：暂存/拒绝/过期不推进、样本加权不变量、提交重放幂等、全参与抵消、联合状态替换拒绝，以及冲突/过时候选拒绝。其中错误缓存分母攻击会重新计算合法的普通 SHA-256 摘要，仍被独立状态重构拒绝；这表明检查不只依赖摘要未被改动，但不构成密码学非伪造证明。

### 不变量的归纳证明

初值 `H_0=0` 与所有 `h_i=0` 一致。若提交前 `N_all H_t=Σ_i n_i h_i`，并且选中集合中的每个客户端只出现一次，则提交后

\[
N_{\rm all}H_{t+1}
=N_{\rm all}H_t+D_t
=\sum_{i\notin I_t}n_i h_i+\sum_{i\in I_t}n_i\Delta_i^t.
\]

这正是提交后客户端缓存的加权总和。拒绝、丢弃及重复通知不应再次加入 `D_t`。该证明依赖固定权重、正确差分和正确提交语义，不是收敛或密码学完整性证明。

### 缓存误差与参与偏差

固定本次随机性与训练配置。令 `δ_i(t)` 表示客户端从当前模型 `W_t` 训练产生的假想新鲜增量，`Δ_i^t` 是实际从旧基版本训练的增量。记 `a_i=n_i/N_all`，入选时 `b_i=n_i/S_t`，未入选时 `b_i=0`。总体新鲜参考方向为 `g_t=Σ_i a_i δ_i(t)`，候选实际方向为 `q_t=H_t+Σ_i b_i(Δ_i^t-h_i)`。

利用缓存不变量，可得精确分解：

\[
q_t-g_t
=\sum_i(b_i-a_i)(\delta_i(t)-h_i)
 +\sum_i b_i(\Delta_i^t-\delta_i(t)).
\]

第一项是参与权重偏移与缓存误差的耦合，第二项仍是训练基版本陈旧误差。进一步由 Cauchy–Schwarz 与三角不等式，

\[
\|q_t-g_t\|
\le
\underbrace{\sqrt{\sum_i (b_i-a_i)^2/a_i}}_{\text{参与权重偏移}}
\underbrace{\sqrt{\sum_i a_i\|\delta_i(t)-h_i\|^2}}_{\text{缓存参考误差}}
 +\sum_i b_i\|\Delta_i^t-\delta_i(t)\|.
\]

这只是一个条件性单 checkpoint 界：缓存接近当前参考时有机会降低第一项；过旧缓存不保证有益，第二项也没有消失。它不要求把当前组级异步调度声称为均匀抽样或无偏估计。实验记录的缓存年龄与已参与用户残差 RMS 只是诊断代理，不能直接测得所有缺席用户的假想新鲜增量或替代上述误差项。

开发试验沿用原始配置及 seeds 42–44，编码为 float64，保留未量化明文基线；种子 52–56 留出。开发阶段原测试集曲线只作固定候选的探索观察，不作为正式调参或泛化证明。完成结果另存 `results_cache_calibration/screen_20261008/screen_report.md`，以该报告的实际完成数为准。

## 11. 联合状态验证的补充近邻核查
