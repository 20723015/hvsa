# 明确实例化基线：生产参数异常行为补测

执行日期：2026-10-23。接续10月20日已完成的四点成本比较；不重复该156回合，不修改其原始数据。沿用用户授权选定的GPVO/VLMRS接口、密码参数与长期密钥策略，原协议适配器不改。

## 本轮预先确定的规格

- GPVO：3072位RSA模数、素数e>N_RSA²、Z*_(N_RSA²)乘法LHF、逐轮新DH会话。VLMRS：BLS12-381、公开根指数7、全邻居、ceil(2N/3)恢复阈值及长期密钥复用。
- 每方案100份小维度独立输入：N=10、M=2，32维和257维各50份；另10份完整维度输入：N=20、M=5、维度7850。VLMRS无边缘角色。
- 六类用例：仅改结果、仅改证明、协调修改结果和证明、相同上传集合的跨轮重放、不同上传集合的跨轮重放、末尾补零的维度异常。每类每方案110次，共1320次验证调用。
- 每方案每个维度先实际执行两个诚实锚点：全部上传、少一人上传。随后执行110份当前诚实上下文。每方案116次完整诚实聚合，两方案232次；全部指定诚实验证者都真正执行检查。
- 重放使用上述固定锚点，当前110份输入独立。不能写成110份独立旧重放载荷。当前输入在两方案间配对；锚点与正式篡改样本分开计数。
- 篡改验证调用一个代表边缘/客户端的真实验证接口，不重复运行完整掩码链。这个范围是验证行为检查，不能写成恶意云已经向所有接收者广播的端到端攻击测量，也不作为性能观测。
- VLMRS每个维度另记录一次“后续恢复长期私钥后恢复先前上传”诊断，共3次，独立于1320次验证调用。

## 记录与验收

输入NPZ、实际上传名单、完整诚实协议角色/消息、真实交付的公开证明、每份篡改载荷、验证耗时及结果均归档。攻击构造仅读取公开载荷和公参，不读取诚实向量或验证密钥；参考和仅用于判断结果是否改变。

本轮不把“拒绝”设为所有用例的验收预期。协调修改、重放或接口异常若被接受，如实记录；执行异常与错误接受分开。只在诚实上下文有效、输入独立性和逐次记录核验通过后形成报告。不能将这个六类矩阵称为穷尽的攻击覆盖或安全证明，更不直接归因于原论文。

驱动：`experiments/point1_compare/run_decided_integrity.py`；独立核验入口：`experiments/point1_compare/validate_decided_integrity.py`。先以2份小输入作新入口试跑并测试证据拒伪，再启动100+10正式样本。试跑不并入正式统计。每个操作1800秒限时，完成前缀逐次保存；串行执行，不启用电源操作。
