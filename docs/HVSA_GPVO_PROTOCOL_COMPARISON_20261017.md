# HVSA 与 GPVO-FL：协议差异、创新点与优劣对比

日期：2026-10-17。按用户选择，本次只做协议与创新分析，不运行对比实验，不修改论文和PPT。

## 1. 结论

两者的基础架构与目标高度接近：均有客户端、边缘、云端和一个完全可信且不合谋的TA，均采用加性掩码、按在线集合提供总掩码、边缘验证，并保护单客户端输入、允许发布聚合结果。不能把这些共同机制作为HVSA相对GPVO-FL的独有创新。

HVSA的明确设计差异是：去掉用户邻居环掩码，仅保留客户端与TA共享的独立掩码；取消由邻居掩码引出的掉线补偿路径；用逐组哈希的签名元数据与同态关系核验组织验证证据，并在验证后由边缘确定性重构模型。这更适合表述为单可信TA前提下的协议简化与证据绑定改造。

结构差异不自动等于新颖性或整体性能领先：仍需证明删减机制后满足所声明的隐私和完整性目标，比较完整链路成本，并核对其他单TA掩码与签名验证近邻。

## 3. 核心机制对照

下式仅为比较掩码结构，将两方案各自待聚合的编码向量统一记为x_i。GPVO主要写本地梯度，当前HVSA第3章写量化后的本地模型；记号统一不表示训练或加权规则天然相同。

GPVO-FL（原文算法2）：

\[
\widetilde x_i=x_i+m_{i,\mathrm{TA}}-m_{i,i-1}+m_{i,i+1}.
\]

HVSA（当前第3章）：

\[
\widetilde x_i=x_i+m_{i,\mathrm{TA}}.
\]

| 维度 | GPVO-FL | HVSA | 结论 |
|---|---|---|---|
| 系统实体 | 客户端、边缘、云、一个TA | 相同四类实体、一个TA | 架构相同，单TA不是独有差异。 |
| 信任基础 | TA完全可信且不合谋；用户与边缘半诚实；云可恶意/懒惰 | 同样依赖可信TA与按规定核验的边缘；云不可信 | 不能声称HVSA消除了对可信方的依赖。 |
| 客户端掩码 | 一份TA掩码和两份邻居环掩码；算法2计算三份PRG输出 | 一份TA共享种子派生的掩码 | 减少两份掩码及邻居密钥依赖，是直接的结构简化。不能由3对1推导完整协议快3倍。 |
| 本地加密与上传 | 可并行；公钥已知时DH可本地计算；主训练向量上传一次 | 可并行；上传一次掩码向量 | 并行加密和一次上传双方都有；不能把GPVO说成必须串行加密。 |
| 掉线处理 | 在线集合总掩码之外，边缘须处理未抵消的邻居环掩码，算法3有掉线掩码补偿项 | TA只为实际在线集合求总掩码，没有邻居环残留项 | HVSA的掉线处理路径更简单。仅针对未上传/退出客户端，不等于恢复丢失的已上传消息。 |
| TA职责 | 产生公共/密钥材料，生成在线用户TA掩码总和，提供验证辅助量 | 保存共享种子，按在线集合重算总掩码及其哈希 | 按在线集合提供总掩码双方已有；TA的总体生成工作均随参与用户与维度增长。 |
| 边缘证据 | 对本地聚合求同态哈希，再生成乘法同态承诺 | 对本地掩码和求LHH，签名绑定轮次、基模型、在线集合摘要、人数/权重与哈希 | 证明结构与绑定对象不同。签名本身不证明求和正确，须配合同态等式核验。 |
| 云端证明处理 | 聚合各组承诺形成c_agg，边缘打开/检验聚合承诺 | 云提供逐组证据列表，边缘核对各组签名并检验哈希关系 | GPVO有承诺聚合能力；HVSA避免该承诺路径，但需处理逐组证据。 |
| 最终模型 | 验证聚合结果后向用户分发 | 先核验原始和，再由边缘确定性重构规范模型 | 可作为协议责任划分差异；需与上下文绑定一起论证，不能仅改名称。 |
| 渐进开销 | 用户O(d)，单边缘O(N_k d)，云O(Md) | 主要聚合路径同阶；边缘还核验M组签名/元数据 | 主要为常数和消息流程差异，不能声称对GPVO有渐进阶数优势。 |
| 验证通信 | 聚合承诺固定大小，相关辅助材料需分别计量 | 固定M下不随d增长；逐组哈希、签名和元数据随M增长 | 两者都有对d维度较友好的验证通信。不能把HVSA的整体证明对M也说成常数。 |

## 4. 对验证路线的理解

GPVO-FL算法3—5的大致关系是：

\[
c_k=\operatorname{Com}(H(\bar X_k),r_k),\quad
c_{\mathrm{agg}}=\prod_k c_k,\quad
\operatorname{Decommit}\left(c_{\mathrm{agg}},H(X_{\mathrm{agg}})H(M_{\mathrm{TA}}),\sum_k r_k\right)=1.
\]

这里M_TA表示TA总掩码。此节只解释原文关系，不引入新安全证明。

HVSA检查签名及如下同态关系：

\[
H(W_{\mathrm{sum}}^{\mathrm{raw}})H(M_{\mathrm{global}})=\prod_k H_k.
\]

签名绑定每个组哈希的来源与上下文，同态等式检查聚合关系。其安全目标应在诚实边缘与可信TA的前提下证明。数字签名不具有与同态承诺完全相同的隐藏性/聚合性，不能笼统表述为“去掉承诺后安全性自然不变”。

## 5. 双方优劣与尚待验证事项

HVSA更容易形成明确优势的方面：

1. 客户端的掩码生成和密钥邻居管理更少。
2. 不需要处理环掩码在客户端掉线后的残留补偿。
3. 已明确把轮次、基模型和在线集合信息纳入签名；在GPVO算法3—5里，这些字段未作为承诺消息逐项列出。这是可展开说明的上下文绑定差异，不等于断言对方必然遭受某种攻击。
4. 验证后模型由边缘确定性重构，为研究点二后续扩展提供一致的规范结果接口；研究点二的检查点、版本补偿与EMA本身不计入研究点一相对GPVO的贡献。

GPVO具有、HVSA不能忽略的方面：

1. 已实现同场景的验证外包、并行掩码与掉线处理，功能覆盖与HVSA接近。
2. 承诺可在云端聚合成一个证明；HVSA现有逐组证据列表的开销随组数增长。
3. 原文不要求所有用户串行训练或串行加密，因此不能用人为顺序网络等待把其正常加密成本放大。
4. 两者的全维LHH计算仍为O(d)，在当前纯Python密码实现中可能成为主要耗时。客户端少两份PRG并不自动带来等比例的系统总加速。

## 6. 合谋边界不能只比较数字

GPVO原文第6页声称云可与至多M-1个边缘、N-1个用户合谋。HVSA将个人输入隐私界定在一个实际发布聚合中至少保留两个非合谋客户端，并允许全部边缘共享视图。不能据此直接宣称其中一者全面更强。

公开聚合和若其余N-1个输入全部已知，最后一个输入可由聚合结果相减得到，这是输出本身所透露的信息。比较时必须统一隐私定义、允许的输出泄露、实际参与集合和诚实边缘条件；不在本次简要对照中采信某一数字等于更强已验证安全性。

尤其要区分：HVSA隐私允许边缘共享视图，不表示所有边缘恶意并拒绝核验时仍有完整性保障。TA始终可信且不合谋是双方共同前提。

## 7. 已有基准不能直接作为胜出证据

`baselines/gpvo_crypto.py`只是单用户加密工作量基准，不含算法3—5的完整验证。它额外生成一个随机种子并向两个邻居作秘密分享，但原文算法2和3未列出这一操作，原文提及Shamir出现在相关工作。该操作不能无说明计入GPVO原协议固有成本。

同一基准给两个邻居各加20ms顺序RTT。原文明确公钥已知时DH可无交互本地计算，用户加密可并行；掉线补偿的通信应按实际发生阶段单列。当前程序的约40ms邻居等待模型，不能当作GPVO每轮必然发生的加密实测成本。

此外，现有HVSA与GPVO基准的模型载荷存在4B/维与8B/维的混用，需要统一合法编码或说明真实格式差异。上述问题未在本次改写程序；本次没有运行新实验。

## 8. 建议的创新点表述

> 针对分层可验证安全聚合中客户端邻居掩码管理与掉线补偿较复杂的问题，在单可信TA假设下，设计客户端独立掩码上传、在线集合驱动总掩码生成、带上下文签名的组级哈希证据核验与验证后模型重构机制，以减少客户端工作和邻居恢复依赖。

“减少客户端工作”在此首先是算法结构的比较；具体耗时、通信和总成本收益须经公平实验量化。“带上下文签名”和“确定性重构”需对应安全命题及实现校验，不能仅以字段存在认定创新充分。

不建议宣称首次分层聚合、首次边缘验证、首次使用单TA、首次一次上传、首次按在线集合生成TA总掩码，或仅凭现有掩码层结果宣布完整协议优于GPVO/SOTA。
