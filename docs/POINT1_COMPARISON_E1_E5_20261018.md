## 1. 结论（按结果填写，限定性表述）

1. **E1正确性**：100组小维度输入的去掩码整数和逐维等于参考；d=7850为同一组合成向量重复回放10次，并非10组独立训练快照。两适配器各110次求和一致且各自诚实验证入口接受。该结果不证明GPVO兼容变体与原文安全等价。
2. **客户端计时仅作记录**：对`20261018-121245_e1/raw.jsonl`重新统计，d=7850的单客户端阶段中位为HVSA 0.1027ms、GPVO变体0.3993ms；每轮全部20个客户端阶段累计后取中位为2.39085ms、8.51655ms。这两种单位不能混用。HVSA计时包含序列化和接收处理，GPVO客户端计时只包掩码；在边界统一前不据此计算正式加速比。小维度的N/d变化，混合中位也不是固定工作点性能。
3. **E5小维度计数**：HVSA既有12类1200次均拒绝；GPVO变体8类800次中700次拒绝、100次相同集合重放接受，不能称作“全部检出”。这一重放行为以固定会话密钥为前提，不归因于原文。大维度E5尚未运行。
4. **补充完整性诊断**：对当前GPVO变体同时修改聚合和与承诺，可被验证入口接受，见§4第6条。原有单独改结果/单独改证据测试没有覆盖这一能力，故E5未达到完整性验收标准。
5. 本报告只记录实际测到的范围，不以有限样本代替安全证明，不据此声称HVSA达到SOTA，也不将兼容变体的行为直接写成原论文漏洞。

- 配置：[configs/mvp.json](../experiments/point1_compare/configs/mvp.json)（`correctness_seed=42`，`verification=full`，`aggregation=equal_weight_integer_sum_then_average`）。
- 机器/库：见各 run 的 `manifest.json`（Python 3.9.15 / numpy 1.26.4 / cryptography 46.0.3 / ecdsa 0.19.1，Windows，单进程串行回放）。
- 量化与域：`×10^6 → int64`；PRG 掩码域 [−10^9, 10^9)（拒绝采样）；原始整数和逐维一致，参考值以 Python int 累加防溢出核对。
- 参数记录：X25519+HKDF、HVSA的P-256 LHH，以及GPVO变体的3072位模数和Z*_{N²}哈希。参数位长不能证明该兼容变体具有约128位整体安全性；同安全目标对齐尚未验收。

## 4. 原文逐步复现中的发现（映射解释决策的实测依据）

1. **LHF接口待澄清**：原文实验设置写P-256，当前代码改为Z*_{N²}乘法哈希。普通EC点序列化一般不保持整数乘法同态，提示哈希/承诺接口需澄清；不能由此宣称任何原文EC实现“必然失败”。替换原语后诚实求和正确不等于安全或性能等价，当前结果须标作兼容变体。
2. **掉线符号选择**：本实现按残留抵消原则确定补偿符号，单元测试覆盖相邻掉线、两人环与组内仅剩一人的情况；正式E4扫描未做。源文变量方向与公式对应仍需核对，测试正确不自动裁定作者所有写法错误。
3. **原文 Round 2 无秘密分享**：`baselines/gpvo_crypto.py:50–51` 的随机种子 Shamir 分享不在原文协议中，不计入 GPVO 成本（计划 §3 对应项已核实）。
4. **跨轮复用是当前变体选择**：原文的每训练轮初始化证据与初稿“长期固定密钥”的断言不一致；需分别计量每轮新初始化与明确标注的复用变体。不得将固定密钥下的重放接受视为作者协议的固有缺陷。
5. **KA 接口顺序**：`KA.gen()` 返回 `(pub, priv)`；历史微基准把第一返回值命名为私钥（计划 §3），新适配器统一 `pub, priv = KA.gen()` 并有对称性测试。

6. **协调篡改诊断，仅适用于当前兼容变体**：记当前正确聚合和为x、承诺为c，攻击者选非零δ，公开构造`x'=x+δ`及`c'=c·LHF(δ)^e mod N²`。由当前哈希与承诺同态性，验证等式仍成立，实际入口接受。构造只使用公共参数、云持有的c和δ，不使用TA的r、h_TA或私钥；TA辅助信息仅由诚实验证端使用。新增回归测试记录此限制，并非安全通过测试。未完成原文完整接口核对前，不将其升级为论文漏洞结论。

### 5b. d=7850 完整链路回放计时（E2 预览观察，非正式性能扫描）

`N=20, M=5, d=7850` 的同一组合成整数向量重复回放10次（本地协议回放口径，单进程串行），不是10组真实训练快照：

| 阶段 | HVSA | GPVO | 说明 |
|---|---|---|---|
| 单轮回放总耗时中位 | ~25.7 s | ~322 s | GPVO 的 LHF（Z\*_{N²}，d 次模幂）+ `e>N²` 承诺主导 |
| 单客户端阶段中位 | 0.1027 ms | 0.3993 ms | 两方案计时包含的序列化/接收操作不同，暂不计算正式加速比 |
| 每轮全部20客户端阶段累计的中位 | 2.39085 ms | 8.51655 ms | 与单客户端单位分开；仅该固定工作点记录 |
| 边缘证据/次 | ~2.3 s | ~14.2 s | HVSA：P-256 LHH；GPVO：LHF mod N² + 承诺模幂 |
| 边缘验证/次 | ~2.4 s | ~29.5 s | HVSA：验签+同态；GPVO：LHF + `h^e·g^r` 重算 |

这些数字只用于估算当前兼容变体的机时，不是原论文GPVO的公平速度对比。E1通过只排除了这些输入上的求和错误，没有排除安全实现、参数、生命周期、缓存和计时口径偏差。

## 6. 敏感项与后续注意

1. **先确认基线**：明确原文P-256哈希与RSA承诺接口、生成元分布及参数复用；不能把研究者替换原语后的成本命名为原论文性能。
2. **补齐完整性检查**：协调修改结果和证据、同轮/跨轮重放、每轮新初始化、原文会话检查，以及d=7850篡改矩阵。先解释兼容变体接受的用例，再开展正式安全性能排名。
3. **统一计算与通信边界**：客户端密码计算、序列化、接收处理拆开；补齐广播副本、证据、TA辅助及初始化消息；掉线掩码披露由谁计算也需按角色重新计量。
4. **参数敏感性不能替代安全论证**：`e=65537`不满足原文`e>N²`，即使保留代数，也不能宣称保留原文全部安全性。若研究这种变体，单独标注并先核查安全条件。当前`com_param_gen`并未提供该变体选择开关。
5. **数据溯源与校验**：旧manifest仅有HEAD提交号，不能定位当时被忽略的源码。复核后的新运行增加配置及源码摘要；旧结果保持原样。现有校验器只做部分内部一致性检查，仍需补齐原始字段、verified/失败数、攻击汇总和源码身份核查。
6. 继续使用“本地协议回放耗时”，不把它当部署端到端时延；本报告不产生SOTA结论。
