TAPFed: Threshold Secure Aggregation for Privacy-Preserving Federated Learning | 
针对问题：
研究方案：
1.基于现有的多客户端函数加密MCFE，设计了一种阈值函数加密（TFE）方案，该方案能够与独立和分散的聚合器进行安全聚合，同时容忍有限数量的恶意聚合器 | 2.设计了基于TFE方案的PPFL框架TAPFED，不需要安全的飞地硬件或去中心化聚合器的P2P连接，避免单点故障。 | 
1.现有的单聚合器安全聚合方法(THE,MIFE,MCFE，成对掩码)对梯度推断攻击有脆弱性，而HE易受隔离攻击和重放攻击 | 2.现有多聚合器安全聚合，需要使用安全隔离硬件或多方安全计算（MPC）技术。需要复杂的点对点通信协议和大规模数据交换，导致系统的可扩展性差,并且存在单点故障问题。 | 
--- slide 3 ---
研究内容一：阈值函数加密方案
针对问题： | 为了解决单点故障和可扩展性的问题，TAPFed构建在多聚合器架构上，以抵御潜在的推理攻击。这与现有的基于秘密共享的多方计算原语不同，因为它不需要聚合器之间的任何对等通信。 |  | 
研究方案：
Setup(λ)：初始化加密系统，生成公共参数和主私钥。 | SKDistribute:将加密密钥分发给每个加密实体（例如参与方）。 | DKGenerate:生成功能解密密钥，使能解密特定的加密数据。 | Encrypt：使用加密密钥加密数据。 | ShareDecrypt：每个解密实体使用自己的解密密钥对加密数据进行解密，最后返回部分解密后的结果。解密开始之前，首先检查解密实体 S 的大小。如果参与的聚合器数量 ∣S∣ 大于或等于阈值t，解密过程才会继续进行。否则，解密失败。 | CombineDecrypt:合并部分解密的结果，恢复最终的计算结果（如内积）。函数首先验证所有聚合器提供的部分解密密文的第一部分否一致。不一致的聚合器将停止解密。这确保了没有错误的解密信息被用于恢复最终结果。

研究内容二：TapFED聚合框架
 | TDSA-Protect：函数对参与方的本地模型更新进行加密，确保训练过程中数据的隐私性，可以选择是否使用差分隐私增强保护。 |  |  | TDSA-Aggregate:聚合来自参与方的加密模型更新,聚合器根据接收到的加密信息请求功能解密密钥dk，并提供模型权重和当前训练轮次的标签，使用生成的dk部分解密， 使用ShareDec 算法得到聚合后的模型更新。 |  | 加密标签确保了每轮训练的加密模型更新不会混淆，避免跨轮次的加密模型更新被错误地合并 |  |  | TDSA-Recover：用加密基础设施提供的解密算法 CombineDec 对聚合器返回的消息进行解密，恢复最终的全局聚合模型。 |  |  |
